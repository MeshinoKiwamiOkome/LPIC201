🚀 システム起動プロセス

BIOS/UEFIからカーネル起動まで、SysVinit・systemd の仕組み、 ランレベル・ターゲット・サービス管理・ログの確認方法を体系的に学びます。

① ブートからカーネル起動まで

重要ポイント①：システムの起動は「BIOS/UEFI → ブートローダ → カーネル → init/systemd」の順で行われる
各フェーズの役割と、BIOS/UEFI・MBR/GPT の違いを正確に理解することが重要です。

起動フロー全体図（クリックで各フェーズの詳細を表示）

1

🔌 BIOS / UEFI

電源投入 → ハードウェア初期化（POST）→ ブートデバイスの選択

2

💾 MBR / GPT

ブートセクタの読み込み → ブートローダの第1ステージを実行

3

🥾 ブートローダ（GRUB2）

起動メニュー表示 → カーネルイメージ（vmlinuz）と initramfs を読み込む

4

⚙️ カーネルの初期化

自己展開 → ハードウェア検出 → initramfs 展開 → ルートFS マウント

5

🌱 init / systemd（PID 1）

最初のプロセス起動 → サービス・デーモンの起動 → ログインプロンプト表示

② SysVinit の概要

重要ポイント②：SysVinit は UNIX System V 由来の伝統的な init システムで、ランレベルに基づいてサービスを管理する
現代のディストリビューションでは systemd に置き換えられていますが、 LPIC-201 の試験範囲として理解が必要です。

/etc/inittab の構造

# /etc/inittab の基本構造（SysVinit）
# 書式：id:ランレベル:アクション:プロセス

# デフォルトのランレベルを設定
id:3:initdefault:

# システム初期化スクリプト
si::sysinit:/etc/rc.d/rc.sysinit

# 各ランレベルの起動スクリプト
l0:0:wait:/etc/rc.d/rc 0
l1:1:wait:/etc/rc.d/rc 1
l2:2:wait:/etc/rc.d/rc 2
l3:3:wait:/etc/rc.d/rc 3
l5:5:wait:/etc/rc.d/rc 5
l6:6:wait:/etc/rc.d/rc 6

# 仮想コンソールの設定（Ctrl+Alt+F1〜F6）
1:2345:respawn:/sbin/mingetty tty1
2:2345:respawn:/sbin/mingetty tty2

# 現在のランレベルを確認
$ runlevel
N 3   # N=前のランレベル（なし）, 3=現在のランレベル

# ランレベルを変更
$ sudo init 3
$ sudo telinit 3   # init へのシンボリックリンク

③ 起動スクリプトとサービスの自動起動

重要ポイント③：SysVinit のサービス管理は /etc/init.d/ のスクリプトと /etc/rc?.d/ のシンボリックリンクで行う
シンボリックリンクのファイル名の先頭文字（S/K）と番号で起動・停止の順序を制御します。

ディレクトリ構造と命名規則

# /etc/init.d/ ：サービス起動スクリプトの本体
$ ls /etc/init.d/
apache2  cron  mysql  networking  ssh  ...

# /etc/rc3.d/ ：ランレベル3で実行するリンク
$ ls /etc/rc3.d/
S01networking  S02rsyslog  S10ssh  S20apache2  S50mysql
K01mysql       K10apache2
# S = Start（起動）  K = Kill（停止）
# 番号が小さいほど先に実行される

# シンボリックリンクの確認
$ ls -la /etc/rc3.d/S20apache2
lrwxrwxrwx 1 root root 17 Jan 1 10:00 /etc/rc3.d/S20apache2 -> ../init.d/apache2

# サービスの手動操作
$ sudo /etc/init.d/apache2 start
$ sudo /etc/init.d/apache2 stop
$ sudo /etc/init.d/apache2 restart
$ sudo /etc/init.d/apache2 status

# service コマンドでも操作できる
$ sudo service apache2 start

サービスの自動起動設定（タブで切り替え）

手動でシンボリックリンクを作成

# ランレベル3でapache2を起動するリンクを作成
$ sudo ln -s /etc/init.d/apache2 /etc/rc3.d/S20apache2

# ランレベル3でapache2を停止するリンクを作成
$ sudo ln -s /etc/init.d/apache2 /etc/rc3.d/K80apache2

# 命名規則
# S = Start（ランレベル移行時に起動）
# K = Kill（ランレベル移行時に停止）
# 数字 = 実行順序（小さいほど先）
# 例：S20apache2 → 起動順序20でapache2を起動

# リンクを削除して自動起動を無効化
$ sudo rm /etc/rc3.d/S20apache2

chkconfig（RHEL/CentOS 系）

# すべてのサービスの自動起動状態を確認
$ chkconfig --list
apache2         0:off   1:off   2:on    3:on    4:on    5:on    6:off
sshd            0:off   1:off   2:on    3:on    4:on    5:on    6:off
mysql           0:off   1:off   2:off   3:off   4:off   5:off   6:off

# 特定サービスの状態確認
$ chkconfig --list apache2

# 自動起動を有効化（ランレベル 2,3,4,5）
$ sudo chkconfig apache2 on

# 自動起動を無効化
$ sudo chkconfig apache2 off

# 特定のランレベルのみ有効化
$ sudo chkconfig --level 35 apache2 on

# サービスを chkconfig に追加
$ sudo chkconfig --add myservice

update-rc.d（Debian/Ubuntu 系）

# 自動起動を有効化（デフォルト設定）
$ sudo update-rc.d apache2 defaults
# → ランレベル 2,3,4,5 で起動（S20）、0,1,6 で停止（K80）

# 自動起動を有効化（順序を指定）
$ sudo update-rc.d apache2 defaults 20 80
#                                      ↑起動順序 ↑停止順序

# 自動起動を無効化（リンクを削除）
$ sudo update-rc.d apache2 remove

# 自動起動を無効化（リンクは残してdisable）
$ sudo update-rc.d apache2 disable

# 自動起動を有効化（disableを解除）
$ sudo update-rc.d apache2 enable

# 特定ランレベルのみ設定
$ sudo update-rc.d apache2 start 20 3 5 . stop 80 0 1 6 .

④ systemd の概要と起動手順

重要ポイント④：systemd は現代の Linux の標準 init システムで、ユニットファイルによる並列起動と依存関係管理が特徴
SysVinit のランレベルに相当する概念として「ターゲット（.target）」を使用します。

SysVinit vs systemd 比較

概念SysVinitsystemd
設定単位シェルスクリプト（/etc/init.d/）ユニットファイル（.service など）
起動方式シリアル（順次）起動並列起動（依存関係に基づく）
ランレベル相当ランレベル 0〜6ターゲット（.target）
デフォルト設定/etc/inittab（initdefault）default.target（シンボリックリンク）
サービス管理service / chkconfig / update-rc.dsystemctl
ログ管理/var/log/syslog などjournald（journalctl で確認）
PID 1/sbin/init/lib/systemd/systemd

ランレベルと systemd ターゲットの対応

ランレベルsystemd ターゲット説明
0poweroff.targetシャットダウン
1 / Srescue.targetシングルユーザー（レスキューモード）
2 / 3 / 4multi-user.targetマルチユーザー（CLI）
5graphical.targetマルチユーザー（GUI）
6reboot.target再起動
—emergency.target緊急モード（最小限の環境）

systemd の起動手順

# systemd の起動フロー
# 1. カーネルが /lib/systemd/systemd を PID 1 として起動
# 2. default.target を確認
$ systemctl get-default
graphical.target

# default.target の実体（シンボリックリンク）
$ ls -la /etc/systemd/system/default.target
lrwxrwxrwx 1 root root 36 /etc/systemd/system/default.target -> /lib/systemd/system/graphical.target

# 3. ターゲットの依存関係を解決して並列起動
# graphical.target → multi-user.target → basic.target → sysinit.target → ...

# デフォルトターゲットの変更
$ sudo systemctl set-default multi-user.target

# 現在のターゲットを変更（即時）
$ sudo systemctl isolate multi-user.target

# systemd のバージョン確認
$ systemctl --version

⑥ Unit 設定ファイル

重要ポイント⑤：systemd のユニットファイルは [Unit]・[Service/Install など]・[Install] の3セクション構成
/lib/systemd/system/（システム提供）と /etc/systemd/system/（ユーザー定義・優先度高）に配置します。

ユニットファイルの種類（クリックで詳細）

.service
デーモン・サービスプロセスを管理。最も一般的なユニット
.target
複数ユニットをグループ化。SysVinit のランレベルに相当
.socket
ソケットベースのアクティベーション。接続時にサービスを起動
.timer
タイマーベースのアクティベーション。cron の代替
.mount
ファイルシステムのマウントポイントを管理
.device
udev が認識したデバイスを表すユニット

.service ユニットファイルの構造

# /lib/systemd/system/apache2.service の例

[Unit]
Description=The Apache HTTP Server
After=network.target remote-fs.target nss-lookup.target
Documentation=https://httpd.apache.org/docs/2.4/

[Service]
Type=forking
Environment=APACHE_STARTED_BY_SYSTEMD=true
ExecStart=/usr/sbin/apachectl start
ExecStop=/usr/sbin/apachectl graceful-stop
ExecReload=/usr/sbin/apachectl graceful
PrivateTmp=true
Restart=on-abort

[Install]
WantedBy=multi-user.target

ユニットファイルの主要ディレクティブ

セクションディレクティブ説明
[Unit]Description=ユニットの説明文
After=このユニットの後に起動するユニット（順序のみ）
Requires=必須の依存ユニット（失敗すると自分も停止）
Wants=任意の依存ユニット（失敗しても自分は継続）
[Service]Type=サービスタイプ（simple/forking/oneshot/notify）
ExecStart=起動コマンド
ExecStop=停止コマンド
ExecReload=設定再読み込みコマンド
Restart=再起動条件（on-failure/always/on-abort）
[Install]WantedBy=enable 時にリンクを作成するターゲット
RequiredBy=enable 時に必須として登録するターゲット

ユニットファイルの配置場所

パス説明優先度
/etc/systemd/system/管理者が作成・変更するユニットファイル最高（システム提供を上書き）
/run/systemd/system/実行時に動的に生成されるユニットファイル中
/lib/systemd/system/パッケージが提供するユニットファイル低
/usr/lib/systemd/system/同上（ディストリビューションによる）低

⑦ systemd のログ（journalctl）

重要ポイント⑥：systemd のログは journald が管理し、journalctl コマンドで確認する
バイナリ形式で保存され、構造化されたフィルタリングが可能です。 /var/log/journal/（永続）または /run/log/journal/（一時）に保存されます。

journalctl の主要コマンド

# 全ログを表示（最古から最新）
$ journalctl

# 最新のログを末尾から表示
$ journalctl -e

# リアルタイムでログを表示（tail -f 相当）
$ journalctl -f

# 最新 N 行を表示
$ journalctl -n 50

# 特定サービスのログを表示
$ journalctl -u apache2
$ journalctl -u apache2 -f    # リアルタイム

# カーネルメッセージのみ表示（dmesg 相当）
$ journalctl -k

# 今回の起動分のログのみ表示
$ journalctl -b
$ journalctl -b -1    # 1つ前の起動分
$ journalctl -b -2    # 2つ前の起動分

# 時間範囲を指定
$ journalctl --since "2026-06-01 10:00:00"
$ journalctl --since "1 hour ago"
$ journalctl --since "09:00" --until "12:00"

# 優先度（ログレベル）でフィルタ
$ journalctl -p err        # error 以上
$ journalctl -p warning    # warning 以上
$ journalctl -p 0          # emergency のみ

# JSON 形式で出力
$ journalctl -o json
$ journalctl -o json-pretty

# ログの使用容量を確認
$ journalctl --disk-usage

# 古いログを削除
$ sudo journalctl --vacuum-size=500M   # 500MB 以下に削減
$ sudo journalctl --vacuum-time=2weeks # 2週間以上古いログを削除

ログの優先度（syslog レベル）

番号名前説明
0emerg緊急：システムが使用不能
1alert警報：即時対応が必要
2crit重大：重大な状態
3errエラー：エラー状態
4warning警告：警告状態
5notice通知：正常だが重要な状態
6info情報：情報メッセージ
7debugデバッグ：デバッグ情報

journald の設定

# /etc/systemd/journald.conf の主要設定
[Journal]
Storage=persistent        # auto/volatile/persistent/none
#   auto       : /var/log/journal/ があれば永続、なければ一時
#   volatile   : /run/log/journal/ に一時保存（再起動で消える）
#   persistent : /var/log/journal/ に永続保存
#   none       : ログを保存しない
SystemMaxUse=500M          # 最大使用容量
SystemKeepFree=1G          # ディスクの最小空き容量
MaxRetentionSec=1month     # ログの最大保存期間
Compress=yes               # ログを圧縮して保存

# 設定変更後は journald を再起動
$ sudo systemctl restart systemd-journald
