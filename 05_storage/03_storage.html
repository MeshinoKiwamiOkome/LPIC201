① デバイスファイルの命名規則

重要ポイント①：Linux のストレージデバイスは /dev/ 以下のデバイスファイルとして表現される。接続インターフェースによって命名規則が異なる
udev が自動的にデバイスファイルを作成・管理します。

ストレージデバイスの命名規則（クリックで詳細）

SATA / SCSI / USB
/dev/sda, /dev/sdb, /dev/sdc...
sd + アルファベット順。パーティションは数字を付加
NVMe SSD
/dev/nvme0n1, /dev/nvme0n1p1...
nvme + コントローラ番号 + n + ネームスペース番号
仮想ディスク（virtio）
/dev/vda, /dev/vdb...
KVM/QEMU 仮想マシンの virtio ブロックデバイス
ループデバイス
/dev/loop0, /dev/loop1...
ISO イメージなどのファイルをブロックデバイスとして扱う
MMC / SD カード
/dev/mmcblk0, /dev/mmcblk0p1...
eMMC・SD カードなどのマルチメディアカード
IDE / PATA（旧来）
/dev/hda, /dev/hdb...
旧来の IDE ディスク（現在はほぼ使用されない）

パーティション操作コマンド

# ブロックデバイスの一覧表示
$ lsblk
NAME        MAJ:MIN RM   SIZE RO TYPE MOUNTPOINTS
sda           8:0    0   500G  0 disk

  └─vg0-lv0 253:0    0 498.5G  0 lvm  /

# fdisk：MBR パーティションの操作（対話式）
$ sudo fdisk /dev/sdb
# m：ヘルプ  n：新規  d：削除  p：一覧  t：タイプ変更  w：書き込み  q：終了

# fdisk でパーティション一覧を表示
$ sudo fdisk -l /dev/sda
Disk /dev/sda: 500 GiB, 536870912000 bytes, 1048576000 sectors
Device     Boot   Start       End   Sectors   Size Id Type

# gdisk：GPT 専用のパーティション操作ツール
$ sudo gdisk /dev/sdb

② ハードディスクの管理

重要ポイント②：hdparm は ATA/SATA ディスクのパラメータを表示・変更するコマンド。ディスクの情報確認やパフォーマンスチューニングに使用する

hdparm コマンド

# hdparm のインストール
$ sudo apt install hdparm

# ディスクの情報を表示（-I = Identity）
$ sudo hdparm -I /dev/sda
/dev/sda:
ATA device, with non-removable media
        Model Number:       SAMSUNG MZNLN256HAJQ-000H1
        Serial Number:      S3EVNX0K123456
        Firmware Revision:  MAV21H3Q
        Transport:          Serial, ATA8-AST, SATA 1.0a, SATA II Extensions
Standards:
        Supported: 9 8 7 6 5
        Likely used: 9
Configuration:
        Logical         max     current
        cylinders       16383   16383
        heads           16      16
        sectors/track   63      63
Capabilities:
        LBA, IORDY(can be disabled)
        Queue depth: 32

# ディスクの読み取り速度をテスト（-t = timing）
$ sudo hdparm -t /dev/sda
/dev/sda:
 Timing buffered disk reads: 1234 MB in  3.00 seconds = 411.33 MB/sec

# キャッシュ読み取り速度をテスト（-T = Timing cache）
$ sudo hdparm -T /dev/sda
/dev/sda:
 Timing cached reads:   12345 MB in  2.00 seconds = 6172.50 MB/sec

# 両方同時にテスト
$ sudo hdparm -Tt /dev/sda

# ディスクのパラメータを表示（-g = geometry）
$ sudo hdparm -g /dev/sda
 geometry      = 60801/255/63, sectors = 976773168, start = 0

# S.M.A.R.T. の有効化
$ sudo hdparm -s 1 /dev/sda   # スタンバイタイムアウトを設定

# ディスクのスリープ状態を確認（-C = Check power）
$ sudo hdparm -C /dev/sda
 drive state is:  active/idle

# ディスクをスリープ状態にする（-y = sleep）
$ sudo hdparm -y /dev/sda

# DMA（Direct Memory Access）を有効化
$ sudo hdparm -d 1 /dev/sda

sdparm コマンド（SCSI デバイス）

# sdparm のインストール
$ sudo apt install sdparm

# SCSI デバイスのパラメータを表示
$ sudo sdparm /dev/sda
    /dev/sda: ATA       SAMSUNG MZNLN256  2H3Q
Read write error recovery mode page:
  AWRE          1  [cha: n, def:  1]
  ARRE          0  [cha: n, def:  0]
  PER           0  [cha: n, def:  0]

# デバイスの識別情報を表示
$ sudo sdparm -i /dev/sda

# キャッシュモードページを表示
$ sudo sdparm -p ca /dev/sda

# ライトキャッシュを有効化
$ sudo sdparm --set=WCE /dev/sda

hdparm の主要オプション一覧

オプション説明
-Iディスクの詳細情報（Identity）を表示
-tバッファリングなしの読み取り速度をテスト
-Tキャッシュ読み取り速度をテスト
-gディスクのジオメトリ情報を表示
-Cディスクの電源状態を確認
-yディスクをスリープ（standby）状態にする
-Yディスクをスリープ（sleep）状態にする
-d 1/0DMA を有効化（1）/ 無効化（0）
-W 1/0ライトキャッシュを有効化（1）/ 無効化（0）
-S Nスタンバイタイムアウトを設定
-a N先読みセクタ数を設定

③ SSD の管理

重要ポイント③：SSD は HDD と異なる特性を持つ。TRIM（fstrim）によって削除済みブロックを SSD に通知してパフォーマンスを維持する
SSD ではランダムアクセスが高速で、デフラグは不要（むしろ有害）です。

SSD と HDD の違い

特性HDDSSD
読み取り速度100〜200 MB/s500MB/s〜7,000MB/s（NVMe）
書き込み速度100〜200 MB/s400MB/s〜6,000MB/s（NVMe）
ランダムアクセス遅い（ヘッドの移動が必要）高速（電気的アクセス）
デフラグ有効（断片化を解消）不要・有害（書き込み回数を消費）
TRIM不要必要（削除済みブロックの通知）
書き込み寿命ほぼ無制限TBW（書き込み総量）で管理
noatime推奨強く推奨（書き込み回数削減）
マウントオプションdefaultsnoatime, discard（TRIM）

TRIM の設定と実行

# SSD が TRIM に対応しているか確認
$ sudo hdparm -I /dev/sda | grep -i trim
           *    Data Set Management TRIM supported (limit 8 blocks)
# * が付いていれば TRIM 対応

# lsblk で DISC-GRAN（TRIM のグラニュラリティ）を確認
$ lsblk -D
NAME    DISC-ALN DISC-GRAN DISC-MAX DISC-ZERO
sda            0      512B       2G         0
# DISC-GRAN が 0 でなければ TRIM 対応

## 方法1：手動 TRIM（fstrim）
# マウント中のファイルシステムに TRIM を実行
$ sudo fstrim /
$ sudo fstrim -v /          # 詳細表示
/: 15.6 GiB (16756506624 bytes) trimmed

# すべてのマウント済みファイルシステムに TRIM を実行
$ sudo fstrim -av
/boot/efi: 491.5 MiB (515530752 bytes) trimmed
/boot: 874.2 MiB (916520960 bytes) trimmed
/: 15.6 GiB (16756506624 bytes) trimmed

## 方法2：定期的な自動 TRIM（systemd timer）
# fstrim.timer を有効化（週1回自動実行）
$ sudo systemctl enable --now fstrim.timer
$ sudo systemctl status fstrim.timer
● fstrim.timer - Discard unused blocks once a week
     Loaded: loaded (/lib/systemd/system/fstrim.timer; enabled)
     Active: active (waiting)
    Trigger: Mon 2026-06-16 00:00:00 JST

## 方法3：マウント時に discard オプション（継続的 TRIM）
# /etc/fstab に discard オプションを追加
UUID=xxxx  /  ext4  defaults,noatime,discard  0 1
# ⚠️  discard オプションは I/O 性能に影響する場合がある
# 定期的な fstrim の方が推奨されることが多い

SSD 最適化のマウントオプション

# SSD 向けの /etc/fstab 設定例
# noatime：アクセス時刻の更新を無効化（書き込み回数削減）
# discard：削除時に即座に TRIM を実行
UUID=xxxx  /       ext4  defaults,noatime,discard  0 1
UUID=yyyy  /home   ext4  defaults,noatime,discard  0 2
UUID=zzzz  /data   xfs   defaults,noatime,discard  0 2

# SSD の書き込み寿命を確認（smartctl）
$ sudo smartctl -a /dev/sda | grep -E "Wear|Written|TBW"
177 Wear_Leveling_Count     0x0013   097   097   000  Pre-fail  Always  -  97
241 Total_LBAs_Written      0x0032   099   099   000  Old_age   Always  -  12345678

④ iSCSI

重要ポイント④：iSCSI（Internet Small Computer System Interface）は TCP/IP ネットワーク経由で SCSI コマンドを転送してリモートストレージをローカルディスクとして使用する技術
iSCSI イニシエータ（クライアント）が iSCSI ターゲット（サーバー）に接続します。

iSCSI の構成

💻 iSCSI イニシエータ
（クライアント）
iscsiadm コマンド
⇄
🌐 TCP/IP ネットワーク
ポート 3260
（iSCSI 標準ポート）
⇄
🗄️ iSCSI ターゲット
（ストレージサーバー）
tgtd / targetcli

iSCSI の用語

用語説明
イニシエータiSCSI クライアント。ストレージにアクセスするホスト
ターゲットiSCSI サーバー。ストレージを提供するホスト
IQNiSCSI Qualified Name。iSCSI デバイスの一意な識別子
例：iqn.2026-01.com.example:storage1
LUNLogical Unit Number。ターゲットが提供するストレージの単位
ポータルターゲットの IP アドレスとポート番号の組み合わせ
セッションイニシエータとターゲット間の接続
CHAPChallenge-Handshake Authentication Protocol。iSCSI の認証方式

iSCSI イニシエータの設定（タブで切り替え）

iSCSI イニシエータのインストールと設定

# iSCSI イニシエータのインストール
$ sudo apt install open-iscsi

# イニシエータ名（IQN）の確認
$ cat /etc/iscsi/initiatorname.iscsi
InitiatorName=iqn.1993-08.org.debian:01:xxxxxxxxxx

# イニシエータ名を変更（任意）
$ sudo vi /etc/iscsi/initiatorname.iscsi
InitiatorName=iqn.2026-01.com.example:client1

# iscsid の設定ファイル
$ cat /etc/iscsi/iscsid.conf
# CHAP 認証を設定する場合
node.session.auth.authmethod = CHAP
node.session.auth.username = username
node.session.auth.password = password

# iscsid デーモンを起動
$ sudo systemctl enable --now iscsid

iSCSI ターゲットの検出

# ターゲットを検出（iSNS または SendTargets）
$ sudo iscsiadm --mode discovery \
    --type sendtargets \
    --portal 192.168.1.100
192.168.1.100:3260,1 iqn.2026-01.com.example:storage1
192.168.1.100:3260,1 iqn.2026-01.com.example:storage2

# 省略形
$ sudo iscsiadm -m discovery -t st -p 192.168.1.100

# 検出されたターゲットの一覧を表示
$ sudo iscsiadm -m node
192.168.1.100:3260,1 iqn.2026-01.com.example:storage1

# ノード（ターゲット）の詳細情報を表示
$ sudo iscsiadm -m node -o show

iSCSI ターゲットへの接続と使用

# ターゲットにログイン（接続）
$ sudo iscsiadm -m node \
    --targetname iqn.2026-01.com.example:storage1 \
    --portal 192.168.1.100:3260 \
    --login
Logging in to [iface: default, target: iqn.2026-01.com.example:storage1, portal: 192.168.1.100,3260]
Login to [iface: default, target: iqn.2026-01.com.example:storage1, portal: 192.168.1.100,3260]: successful

# すべてのターゲットにログイン
$ sudo iscsiadm -m node --loginall=all

# 接続後：新しいブロックデバイスが作成される
$ lsblk
sdb      8:16   0  100G  0 disk   ← iSCSI ディスクとして認識

# 通常のディスクと同様に使用可能
$ sudo fdisk /dev/sdb
$ sudo mkfs.ext4 /dev/sdb1
$ sudo mount /dev/sdb1 /mnt/iscsi

# 現在のセッションを確認
$ sudo iscsiadm -m session
tcp: [1] 192.168.1.100:3260,1 iqn.2026-01.com.example:storage1 (non-flash)

# ターゲットからログアウト（切断）
$ sudo umount /mnt/iscsi
$ sudo iscsiadm -m node \
    --targetname iqn.2026-01.com.example:storage1 \
    --portal 192.168.1.100:3260 \
    --logout

# 起動時に自動ログインを設定
$ sudo iscsiadm -m node \
    --targetname iqn.2026-01.com.example:storage1 \
    -o update \
    -n node.startup \
    -v automatic

iSCSI ターゲットの設定（サーバー側）

# targetcli のインストール（現代の標準）
$ sudo apt install targetcli-fb

# targetcli の起動
$ sudo targetcli
targetcli shell version 2.1.53
Copyright 2011-2013 by Datera, Inc and others.
For help on commands, type 'help'.
/>

# targetcli でのターゲット設定例
# バックストア（ストレージ）の作成
/> backstores/block create name=disk1 dev=/dev/sdb
/> backstores/fileio create name=file1 file_or_dev=/data/iscsi.img size=10G

# iSCSI ターゲットの作成
/> iscsi/ create iqn.2026-01.com.example:storage1

# LUN の設定
/> iscsi/iqn.2026-01.com.example:storage1/tpg1/luns create /backstores/block/disk1

# ACL（アクセス制御）の設定
/> iscsi/iqn.2026-01.com.example:storage1/tpg1/acls create iqn.1993-08.org.debian:01:client1

# 設定を保存して終了
/> saveconfig
/> exit

# target サービスを起動
$ sudo systemctl enable --now target
