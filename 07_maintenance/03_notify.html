① ログインフローとメッセージファイル

重要ポイント①：ログイン前は /etc/issue（ローカル）または /etc/issue.net（SSH）が表示され、ログイン後は /etc/motd が表示される
各ファイルの表示タイミングと用途の違いを正確に理解しましょう。

メッセージファイルの比較

ファイル表示タイミング対象用途
/etc/issue ログイン前（認証前） ローカルコンソール OS情報・警告メッセージ・法的注意事項
/etc/issue.net ログイン前（認証前） SSH・ネットワーク接続 SSH バナー（/etc/ssh/sshd_config の Banner 設定が必要）
/etc/motd ログイン後（認証後） すべてのユーザー 今日のお知らせ・メンテナンス情報・システム情報
/etc/motd.d/ ログイン後 すべてのユーザー 動的 MOTD のスクリプトを格納するディレクトリ（Ubuntu）
/run/motd.dynamic ログイン後 すべてのユーザー 動的に生成された MOTD（Ubuntu）

② /etc/issue と /etc/issue.net

/etc/issue の設定

# /etc/issue の内容確認
$ cat /etc/issue
Ubuntu 24.04.1 LTS \n \l

# /etc/issue のエスケープシーケンス
# \n : ホスト名
# \l : ログイン端末名（tty1 など）
# \r : カーネルリリース番号
# \v : カーネルバージョン
# \m : アーキテクチャ（x86_64 など）
# \o : NIS ドメイン名
# \d : 現在の日付
# \t : 現在の時刻
# \s : OS 名（Linux）

# カスタマイズ例
$ sudo vi /etc/issue
*****************************************************
*  WARNING: Authorized access only!                *
*  Unauthorized access is strictly prohibited.     *
*****************************************************
Host: \n  Kernel: \r  Arch: \m
Terminal: \l

# ローカルコンソールのログイン画面で表示される

/etc/issue.net と SSH バナーの設定

# /etc/issue.net の内容（SSH 接続時のバナー）
$ cat /etc/issue.net
Ubuntu 24.04.1 LTS

# SSH バナーを有効化するには sshd_config を編集
$ sudo vi /etc/ssh/sshd_config
Banner /etc/issue.net

# SSH サービスを再起動して設定を反映
$ sudo systemctl restart sshd

# SSH 接続時に表示されるバナーの例
*****************************************************
*  This system is for authorized users only.       *
*  All activities may be monitored and recorded.   *
*****************************************************

# ⚠️ /etc/issue.net ではエスケープシーケンスが使えない
# （\n や \r などは展開されない）

③ /etc/motd（Message of the Day）

重要ポイント②：/etc/motd はログイン後に表示されるメッセージ。メンテナンス予告・重要なお知らせ・システム情報を記載する
Ubuntu などでは /etc/motd.d/ のスクリプトで動的に生成される場合があります。

/etc/motd の設定

# /etc/motd の内容確認
$ cat /etc/motd

# /etc/motd を編集（メンテナンス予告の例）
$ sudo vi /etc/motd
============================================================
  Welcome to myserver.example.com
============================================================

  [NOTICE] Scheduled maintenance:
  Date: 2026-06-20 02:00 - 04:00 JST
  Impact: System will be unavailable during this period.

  Please save your work before the maintenance window.
  Contact: admin@example.com
============================================================

# メンテナンス終了後は内容を削除または更新
$ sudo truncate -s 0 /etc/motd   # ファイルを空にする
$ sudo > /etc/motd               # 同様に空にする

動的 MOTD（Ubuntu 系）

# Ubuntu では /etc/update-motd.d/ のスクリプトで動的 MOTD を生成
$ ls /etc/update-motd.d/
00-header         10-help-text      50-landscape-sysinfo
50-motd-news      80-esm            91-release-upgrade
95-hwe-eol        97-overlayroot    98-fsck-at-reboot
98-reboot-required

# 各スクリプトは実行可能なシェルスクリプト
$ cat /etc/update-motd.d/00-header
#!/bin/sh
printf "Welcome to %s (%s %s %s)\n" "$(lsb_release -s -d)" \
    "$(uname -o)" "$(uname -r)" "$(uname -m)"

# カスタムスクリプトを追加（システム情報を表示する例）
$ sudo vi /etc/update-motd.d/10-sysinfo
#!/bin/bash
echo ""
echo "=== System Information ==="
echo "  Hostname : $(hostname)"
echo "  Uptime   : $(uptime -p)"
echo "  Load     : $(cat /proc/loadavg | awk '{print $1, $2, $3}')"
echo "  Memory   : $(free -h | awk '/^Mem/{print $3 "/" $2}')"
echo "  Disk     : $(df -h / | awk 'NR==2{print $3 "/" $2 " (" $5 ")"}')"
echo "  IP Addr  : $(hostname -I | awk '{print $1}')"
echo "=========================="

# 実行権限を付与
$ sudo chmod 755 /etc/update-motd.d/10-sysinfo

# 動的 MOTD を手動で生成・確認
$ sudo run-parts /etc/update-motd.d/

④ ログイン中ユーザーへの通知

重要ポイント③：wall コマンドはすべてのログインユーザーに、write コマンドは特定ユーザーにメッセージを送信する。mesg コマンドでメッセージ受信を制御できる

通知コマンドの使い方（インタラクティブ）

コマンドを選択して使い方と出力例を確認しましょう

通知コマンドの比較表

コマンド送信先特徴
wall すべてのログインユーザー ブロードキャスト。mesg n でも root の wall は届く場合がある
write ユーザー名 特定のユーザー 1対1のメッセージ送信。mesg n のユーザーには送れない
mesg y/n —（受信制御） 自分への write/wall メッセージの受信を許可（y）/拒否（n）
who —（確認） 現在ログイン中のユーザーと端末を表示
w —（確認） ログイン中ユーザーの詳細情報（実行コマンド・アイドル時間）
shutdown -h +N "メッセージ" すべてのログインユーザー シャットダウン通知と同時にメッセージを送信

wall コマンドのターミナル表示例

bob@myserver — wall メッセージ受信
bob@myserver:~$ vim important.txt
（vim で編集中...）
Broadcast message from root@myserver (pts/0) (Fri Jun 13 15:00:00 2026):
System will be rebooted in 10 minutes for maintenance.
Please save your work!
（vim の画面が一時的に中断されてメッセージが表示される）
