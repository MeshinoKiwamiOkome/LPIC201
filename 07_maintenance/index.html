① ソースインストールの全体フロー

重要ポイント①：ソースからのインストールは「展開 → configure → make → make install」の4ステップが基本
パッケージマネージャが提供しないソフトウェアや、最新版・カスタムオプションが必要な場合に使用します。

ビルドフロー（クリックで各ステップの詳細を表示）

1

📥 ソースアーカイブのダウンロード

wget / curl で .tar.gz や .tar.bz2 を取得

2

📦 アーカイブの展開

tar xzf / tar xjf でソースコードを展開

3

⚙️ configure スクリプトの実行

./configure でシステム環境を確認し Makefile を生成

4

🔨 コンパイル（make）

make で Makefile に従ってソースコードをコンパイル

5

📂 インストール（make install）

sudo make install でバイナリ・ライブラリ・設定ファイルを配置

② ソースの展開

tar コマンドによるアーカイブ操作

## アーカイブ形式と展開コマンド

# .tar.gz（gzip 圧縮）
$ tar xzf software-1.0.tar.gz
$ tar xzvf software-1.0.tar.gz    # -v で詳細表示

# .tar.bz2（bzip2 圧縮）
$ tar xjf software-1.0.tar.bz2
$ tar xjvf software-1.0.tar.bz2

# .tar.xz（xz 圧縮）
$ tar xJf software-1.0.tar.xz

# .tar（圧縮なし）
$ tar xf software-1.0.tar

# 展開先ディレクトリを指定（-C）
$ tar xzf software-1.0.tar.gz -C /usr/local/src/

# 展開前に内容を確認（-t = list）
$ tar tzf software-1.0.tar.gz | head -20
software-1.0/
software-1.0/configure
software-1.0/Makefile.in
software-1.0/README
software-1.0/src/
software-1.0/src/main.c

# アーカイブを作成（参考）
$ tar czf myproject-1.0.tar.gz myproject-1.0/
$ tar cjf myproject-1.0.tar.bz2 myproject-1.0/

オプション意味説明
xextractアーカイブを展開
ccreateアーカイブを作成
tlistアーカイブの内容を一覧表示
ffileアーカイブファイルを指定（必須）
vverbose処理中のファイルを表示
zgzipgzip 圧縮・展開（.tar.gz）
jbzip2bzip2 圧縮・展開（.tar.bz2）
Jxzxz 圧縮・展開（.tar.xz）
C ディレクトリchange directory展開先・作成元ディレクトリを指定
ppreserveパーミッションを保持

# 典型的なソースパッケージの構成
$ ls software-1.0/

# まず README と INSTALL を読む
$ cat README
$ cat INSTALL

③ configure スクリプト

重要ポイント②：configure スクリプトはシステムの環境（コンパイラ・ライブラリ・ヘッダファイル）を確認して Makefile を生成する。--prefix でインストール先を指定できる

configure の主要オプション

# 利用可能なオプションを確認
$ ./configure --help
Usage: ./configure [OPTION]... [VAR=VALUE]...

Installation directories:
  --prefix=PREFIX         install architecture-independent files in PREFIX
                          [/usr/local]
  --exec-prefix=EPREFIX   install architecture-dependent files in EPREFIX
  --bindir=DIR            user executables [EPREFIX/bin]
  --sbindir=DIR           system admin executables [EPREFIX/sbin]
  --libdir=DIR            object code libraries [EPREFIX/lib]
  --includedir=DIR        C header files [PREFIX/include]
  --mandir=DIR            man documentation [PREFIX/share/man]
  --sysconfdir=DIR        read-only single-machine data [PREFIX/etc]

# 標準的な configure の実行
$ ./configure --prefix=/usr/local

# /usr にインストール（システム全体向け）
$ ./configure --prefix=/usr

# 特定ディレクトリにインストール（独立管理向け）
$ ./configure --prefix=/opt/software-1.0

# 機能の有効化・無効化
$ ./configure --enable-ssl --disable-debug --with-zlib

# 環境変数でコンパイラ・フラグを指定
$ ./configure CC=gcc CFLAGS="-O2 -march=native"

# configure 実行後に生成されるファイル
$ ls -la
Makefile          # ← configure が Makefile.in から生成
config.h          # ← システム設定のヘッダファイル
config.log        # ← configure の実行ログ（エラー調査に使用）
config.status     # ← 設定を再現するためのスクリプト

configure のインストール先ディレクトリ

オプションデフォルト（--prefix=/usr/local）説明
--prefix/usr/localインストールのベースディレクトリ
--bindir/usr/local/bin実行ファイル
--sbindir/usr/local/sbin管理者用実行ファイル
--libdir/usr/local/libライブラリ
--includedir/usr/local/includeC ヘッダファイル
--sysconfdir/usr/local/etc設定ファイル
--mandir/usr/local/share/manman ページ
--datadir/usr/local/shareアーキテクチャ非依存データ
⚠️ configure が失敗する主な原因
・開発ツールがない：sudo apt install build-essential でインストール
・ライブラリの開発ファイルがない：libssl-dev など -dev パッケージが必要
・エラーの確認：config.log に詳細なエラー情報が記録される

④ Makefile の構造

重要ポイント③：Makefile はターゲット・依存関係・コマンドで構成される。make コマンドは Makefile に従ってビルドを実行する
コマンド行は必ずタブ文字で始める（スペースは不可）。

Makefile の基本構造

# Makefile の基本構造
# 変数の定義
CC = gcc
CFLAGS = -Wall -O2
PREFIX = /usr/local
# ターゲット: 依存ファイル
# [TAB]コマンド
all: software
software: src/main.o src/utils.o
$(CC) $(CFLAGS) -o software src/main.o src/utils.o
src/main.o: src/main.c include/main.h
$(CC) $(CFLAGS) -c -o src/main.o src/main.c
src/utils.o: src/utils.c include/utils.h
$(CC) $(CFLAGS) -c -o src/utils.o src/utils.c
install:
install -m 755 software $(PREFIX)/bin/software
clean:
rm -f src/*.o software
distclean: clean
rm -f Makefile config.h config.log config.status
.PHONY: all install clean distclean

Makefile の構文ルール

要素書式説明
ターゲットターゲット名: 依存ファイル生成するファイル名またはアクション名
依存関係コロンの右側このターゲットが依存するファイルやターゲット
コマンド[TAB]コマンドターゲットを生成するシェルコマンド（必ずタブ文字）
変数VAR = 値 / $(VAR)変数の定義と参照
フォニーターゲット.PHONY: ターゲット名ファイルを生成しないターゲット（clean など）
コメント# コメント行頭の # 以降はコメント

Makefile の変数

# Makefile の変数定義と参照

# 単純代入（= ）: 再帰的展開（参照時に評価）
CC = gcc
CFLAGS = -Wall -O2

# 即時代入（:= ）: 定義時に評価
SRCS := $(wildcard src/*.c)
OBJS := $(SRCS:.c=.o)

# 変数の参照
$(CC) $(CFLAGS) -o $@ $^

# 自動変数
# $@  : 現在のターゲット名
# $^  : すべての依存ファイル
# $<  : 最初の依存ファイル
# $*  : パターンマッチのステム（% に一致した部分）

# 暗黙のルール（パターンルール）
%.o: %.c
	$(CC) $(CFLAGS) -c -o $@ $<

# 環境変数の参照
PREFIX ?= /usr/local   # ?= : 未定義の場合のみ代入

⑤ コンパイルとインストール

make コマンドの使い方

## make コマンドの基本操作

# デフォルトターゲット（all）を実行
$ make

# 特定のターゲットを実行
$ make all
$ make install
$ make clean
$ make distclean
$ make test
$ make uninstall

# 並列コンパイル（-j = ジョブ数）
$ make -j4                  # 4並列
$ make -j$(nproc)           # CPU コア数に合わせて並列化

# 変数をコマンドラインで上書き
$ make CC=clang             # コンパイラを変更
$ make CFLAGS="-O3 -g"      # コンパイルフラグを変更
$ make PREFIX=/opt/software  # インストール先を変更

# ドライラン（実際には実行しない）
$ make -n                    # 実行されるコマンドを表示
$ make --dry-run

# 詳細表示
$ make V=1                   # 詳細なコンパイルコマンドを表示
$ make VERBOSE=1

# エラーを無視して続行（-k）
$ make -k

# 特定のディレクトリで make を実行（-C）
$ make -C /path/to/source

完全なビルド・インストール手順（実例）

ソフトウェアを選択して実際のビルド手順を確認しましょう

make の主要ターゲット一覧

ターゲット説明
make / make allデフォルトターゲット。通常はコンパイルを実行
make installコンパイル済みファイルをシステムにインストール
make cleanコンパイル済みオブジェクトファイル（.o）と実行ファイルを削除
make distcleanconfigure が生成したファイル（Makefile・config.h など）も削除
make test / make checkテストスイートを実行
make uninstallインストールしたファイルを削除（対応している場合）
make dist配布用アーカイブ（.tar.gz）を作成

ビルド後のファイル管理

# インストールされたファイルを確認
$ find /usr/local/bin /usr/local/lib /usr/local/include \
    -name "software*" -ls

# DESTDIR を使ってインストールファイルを確認（パッケージ作成に有用）
$ sudo make install DESTDIR=/tmp/staging
$ find /tmp/staging -ls

# ビルドディレクトリのクリーンアップ
$ make clean        # .o ファイルと実行ファイルを削除
$ make distclean    # Makefile・config.h なども削除（configure 前の状態に戻す）

# ソースディレクトリを削除（インストール後に不要な場合）
$ cd ..
$ rm -rf software-1.0/

# 共有ライブラリのキャッシュを更新（ライブラリをインストールした場合）
$ sudo ldconfig

# インストールされたコマンドを確認
$ which software
/usr/local/bin/software
$ software --version
✅ ソースインストールのベストプラクティス
① --prefix を明示的に指定：--prefix=/usr/local または --prefix=/opt/ソフトウェア名
② チェックサムで整合性確認：ダウンロード後に sha256sum で確認
③ README・INSTALL を読む：ソフトウェア固有の手順がある場合がある
④ build-essential をインストール：sudo apt install build-essential
⑤ config.log でエラー確認：configure 失敗時は config.log を確認
⑥ make -j$(nproc) で並列化：ビルド時間を短縮できる
