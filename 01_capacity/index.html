① キャパシティプランニングとは

重要ポイント①：キャパシティプランニングとは、現在のリソース使用状況を把握し、将来の需要に備えてシステムを適切に管理・拡張する計画的プロセスである
単にリソースを監視するだけでなく、傾向の分析・予測・対策立案までを含む継続的な活動です。

キャパシティプランニングの目的

目的内容
パフォーマンス確保 ユーザーやアプリケーションが必要とするリソースを常に確保する
障害の予防 リソース枯渇による障害を事前に検知・回避する
コスト最適化 過剰なリソース確保を避け、適切な投資計画を立てる
将来予測 ビジネス成長に合わせたシステム拡張計画を策定する

対象となる主なリソース

🖥️ CPU
プロセッサの使用率・ロードアベレージ・コア数の適切性
🧠 メモリ（RAM）
物理メモリ使用量・スワップ使用量・メモリリーク検出
💾 ディスク（I/O）
ディスク使用量・読み書き速度・inode使用率
🌐 ネットワーク
帯域使用率・パケットロス・レイテンシ

③ ロードアベレージ（Load Average）

重要ポイント②：ロードアベレージはシステムの負荷を示す指標で、実行待ちプロセス数の平均値
uptime や top コマンドで確認でき、 1分・5分・15分の3つの平均値が表示されます。

ロードアベレージの確認

# uptime コマンドで確認
$ uptime
 10:30:45 up 3 days,  2:15,  2 users,  load average: 0.52, 0.48, 0.41
#                                        ↑1分  ↑5分  ↑15分

# top コマンドの1行目にも表示される
$ top
top - 10:30:45 up 3 days,  2:15,  2 users,  load average: 0.52, 0.48, 0.41

# /proc/loadavg でも確認可能
$ cat /proc/loadavg
0.52 0.48 0.41 1/312 18423
#  ↑1分 ↑5分 ↑15分  ↑実行中/総プロセス数  ↑最後に生成されたPID

ロードアベレージ インタラクティブデモ

CPUコア数とロードアベレージを変えて、システムの状態を確認してみましょう

0.52
⚠️ ロードアベレージの解釈
ロードアベレージの値はCPUコア数を基準に判断します。
例：4コアのシステムでロードアベレージが 4.0 → 各コアがちょうど100%使用中
例：4コアのシステムでロードアベレージが 8.0 → プロセスが実行待ちになっている（過負荷）
1分値が急上昇しているが15分値は低い→ 一時的な負荷スパイク
3つの値がすべて高い→ 継続的な過負荷状態

ロードアベレージに関連するコマンド一覧

コマンド確認できる情報主なオプション
uptime 稼働時間・ロードアベレージ -p（稼働時間のみ表示）
top リアルタイムのCPU・メモリ・プロセス情報 -b（バッチモード）-n（繰り返し回数）
w ログインユーザー・ロードアベレージ —
cat /proc/loadavg ロードアベレージ・プロセス数・最新PID —
sar -q 過去のロードアベレージ履歴 -f（ファイル指定）-s/-e（時間範囲）
