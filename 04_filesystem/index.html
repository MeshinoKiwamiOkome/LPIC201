② マウントとアンマウント

重要ポイント②：mount コマンドでファイルシステムをディレクトリツリーに接続し、umount で切り離す。/etc/fstab で起動時の自動マウントを設定する
マウントポイントは空のディレクトリである必要があります。

マウントの概念図

💾 デバイス
/dev/sdb1
→ mount →
📁 マウントポイント
/mnt/data
→
✅ アクセス可能
ls /mnt/data

mount コマンドの基本

# 基本的なマウント
$ sudo mount /dev/sdb1 /mnt/data

# ファイルシステムタイプを指定
$ sudo mount -t ext4 /dev/sdb1 /mnt/data
$ sudo mount -t xfs  /dev/sdc1 /mnt/xfsdata
$ sudo mount -t vfat /dev/sdd1 /mnt/usb
$ sudo mount -t nfs  192.168.1.10:/exports /mnt/nfs

# マウントオプションを指定（-o）
$ sudo mount -o ro /dev/sdb1 /mnt/data         # 読み取り専用
$ sudo mount -o rw,noexec /dev/sdb1 /mnt/data  # 読み書き・実行不可
$ sudo mount -o remount,rw /                   # 再マウント（ro→rw）

# UUID で指定（デバイス名が変わっても安全）
$ sudo mount UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx /mnt/data

# ISO イメージをループマウント
$ sudo mount -o loop ubuntu.iso /mnt/iso
$ sudo mount -t iso9660 -o loop ubuntu.iso /mnt/iso

# tmpfs をマウント
$ sudo mount -t tmpfs -o size=512m tmpfs /tmp

# 現在のマウント状態を確認
$ mount                    # すべてのマウントを表示
$ mount | grep sdb        # 特定デバイスを確認
$ findmnt                  # ツリー形式で表示

主要なマウントオプション

マウントオプションを選択して意味と用途を確認しましょう

umount コマンド

# マウントポイントを指定してアンマウント
$ sudo umount /mnt/data

# デバイスを指定してアンマウント
$ sudo umount /dev/sdb1

# 使用中でアンマウントできない場合の確認
$ sudo umount /mnt/data
umount: /mnt/data: target is busy

# 使用中のプロセスを確認
$ lsof /mnt/data          # /mnt/data を使用中のプロセス一覧
$ fuser -m /mnt/data       # 使用中のプロセスIDを表示
$ fuser -km /mnt/data      # 使用中のプロセスを強制終了してアンマウント

# 遅延アンマウント（使用中プロセスが終了したらアンマウント）
$ sudo umount -l /mnt/data  # lazy umount

# 強制アンマウント（NFS などが応答しない場合）
$ sudo umount -f /mnt/nfs   # force umount（危険）

# /etc/fstab に記載されたすべてをマウント
$ sudo mount -a

# /etc/fstab に記載されたすべてをアンマウント
$ sudo umount -a

/etc/fstab の設定

# /etc/fstab の書式
# デバイス  マウントポイント  FSタイプ  オプション  dump  pass

# 書式の各フィールド説明
# 1. デバイス：/dev/sda1 または UUID=xxxx または LABEL=xxx
# 2. マウントポイント：/boot など
# 3. FSタイプ：ext4, xfs, vfat, nfs, swap など
# 4. オプション：defaults, ro, noexec など
# 5. dump：0=バックアップ対象外, 1=対象（現在はほぼ0）
# 6. pass：fsck の順序（0=スキップ, 1=最初, 2=後）

# /etc/fstab の例
# <device>                                <mountpoint> <type>  <options>              <dump> <pass>
UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx /            ext4    defaults               0      1
UUID=yyyyyyyy-yyyy-yyyy-yyyy-yyyyyyyyyyyy /boot        ext4    defaults               0      2
UUID=XXXX-XXXX                           /boot/efi    vfat    umask=0077             0      1
UUID=zzzzzzzz-zzzz-zzzz-zzzz-zzzzzzzzzzzz none        swap    sw                     0      0
tmpfs                                    /tmp         tmpfs   defaults,noexec,nosuid 0      0
192.168.1.10:/exports                    /mnt/nfs     nfs     defaults,_netdev       0      0
/dev/sr0                                 /mnt/cdrom   iso9660 noauto,user,ro         0      0

# pass フィールドの意味
# 0 : fsck をスキップ（swap・NFS・tmpfs など）
# 1 : 最初に fsck（ルートファイルシステム /）
# 2 : 2番目以降に fsck（その他のパーティション）
⚠️ /etc/fstab の設定ミスに注意
/etc/fstab の設定ミスはシステムが起動しなくなる原因になります。
・変更後は必ず sudo mount -a でエラーがないか確認する
・デバイス名（/dev/sda1）は再起動後に変わる可能性があるため、UUID で指定することを推奨
・UUID は blkid または lsblk -f で確認できる

③ sync コマンド

重要ポイント③：sync はカーネルのバッファキャッシュをディスクに書き込むコマンド。アンマウント前・シャットダウン前に実行することでデータ損失を防ぐ
Linux はパフォーマンスのためにディスク書き込みをバッファリング（非同期I/O）します。 sync はそのバッファを強制的にフラッシュします。

バッファキャッシュの仕組みと sync

【書き込みの流れ】
アプリケーション → write() → カーネルバッファキャッシュ → sync → ディスク
・通常：カーネルが適切なタイミングで自動的にフラッシュ（pdflush/writeback）
・sync ：即座にすべてのバッファをディスクに書き込む
・async：デフォルト。書き込みをバッファリングして後でまとめて書き込む（高速）
・sync オプション：マウント時に sync オプションを指定すると常に同期書き込み（低速） 
# バッファキャッシュをすべてディスクに書き込む
$ sync

# 複数回実行することもある（確実性のため）
$ sync; sync; sync

# アンマウント前に sync を実行（安全のため）
$ sync && sudo umount /mnt/usb

# ページキャッシュを手動で解放（メモリ解放）
$ sync
$ echo 1 | sudo tee /proc/sys/vm/drop_caches  # ページキャッシュ解放
$ echo 2 | sudo tee /proc/sys/vm/drop_caches  # スラブキャッシュ解放
$ echo 3 | sudo tee /proc/sys/vm/drop_caches  # 両方解放
# ※ drop_caches の前に sync を実行してダーティページを書き込む

# ダーティページの状態を確認
$ cat /proc/meminfo | grep Dirty
Dirty:              1024 kB   # ← まだディスクに書かれていないデータ
Writeback:             0 kB   # ← 現在書き込み中のデータ
✅ sync が重要な場面
・USB メモリのアンマウント前：sync && umount /mnt/usb
・緊急シャットダウン前：sync; sync; sync → shutdown -h now
・カーネルパニック後の再起動前：Magic SysRq キーで s（sync）を実行
・ベンチマーク測定前：キャッシュの影響を排除するため sync + drop_caches

④ スワップ

重要ポイント④：スワップはRAMが不足した場合にディスクをRAMの代わりに使用する領域。swapon・swapoff で管理する
スワップ領域は専用パーティション（スワップパーティション）またはスワップファイルとして作成できます。

スワップパーティションの作成

# 1. パーティションを作成（fdisk または parted）
$ sudo fdisk /dev/sdb
# → n（新規）→ パーティション番号 → サイズ → t（タイプ）→ 82（Linux swap）→ w（書き込み）

# 2. スワップ領域として初期化
$ sudo mkswap /dev/sdb1
Setting up swapspace version 1, size = 2 GiB (2147479552 bytes)
no label, UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

# 3. スワップを有効化
$ sudo swapon /dev/sdb1

# 4. /etc/fstab に追記して永続化
$ echo '/dev/sdb1 none swap sw 0 0' | sudo tee -a /etc/fstab
# または UUID で指定（推奨）
$ echo 'UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx none swap sw 0 0' | sudo tee -a /etc/fstab

# 確認
$ swapon --show

スワップファイルの作成

# 1. スワップファイルを作成（fallocate が高速）
$ sudo fallocate -l 2G /swapfile
# fallocate が使えない場合は dd を使用
$ sudo dd if=/dev/zero of=/swapfile bs=1M count=2048

# 2. パーミッションを設定（root のみ読み書き可能）
$ sudo chmod 600 /swapfile

# 3. スワップ領域として初期化
$ sudo mkswap /swapfile
Setting up swapspace version 1, size = 2 GiB (2147479552 bytes)

# 4. スワップを有効化
$ sudo swapon /swapfile

# 5. /etc/fstab に追記して永続化
$ echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab

# 確認
$ swapon --show
NAME      TYPE  SIZE USED PRIO
/swapfile file    2G   0B   -2

swapon / swapoff コマンド

# スワップを有効化
$ sudo swapon /dev/sdb1          # パーティション
$ sudo swapon /swapfile           # ファイル
$ sudo swapon -a                  # /etc/fstab の全スワップを有効化

# 優先度を指定してスワップを有効化（高い値が優先）
$ sudo swapon -p 10 /dev/sdb1     # 優先度 10
$ sudo swapon -p 5  /swapfile      # 優先度 5（低い）

# スワップを無効化
$ sudo swapoff /dev/sdb1
$ sudo swapoff /swapfile
$ sudo swapoff -a                 # すべてのスワップを無効化

# スワップの一覧と詳細表示
$ swapon --show
$ swapon -v                       # 詳細表示

# スワップの優先度について
# /etc/fstab の sw オプションで優先度を指定
# UUID=xxx none swap sw,pri=10 0 0
# 優先度が同じ場合はラウンドロビンで使用（パフォーマンス向上）
