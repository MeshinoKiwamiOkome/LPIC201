① ext2/ext3 ファイルシステムの構造

重要ポイント①：ext2/3/4 はブロックグループ構造を持ち、各グループにスーパーブロック・inode テーブル・データブロックが含まれる
この構造を理解することで、fsck の動作や障害回復の仕組みを把握できます。

② ファイルシステムのチェック（fsck / e2fsck）

重要ポイント②：fsck はファイルシステムの整合性を検査・修復するコマンド。必ずアンマウント状態で実行する
マウント中のファイルシステムに対して fsck を実行するとデータが破損する危険があります。

fsck / e2fsck の基本操作

# fsck の基本（アンマウント状態で実行すること！）
$ sudo fsck /dev/sdb1
$ sudo fsck -t ext4 /dev/sdb1   # FSタイプを明示

# e2fsck（ext2/3/4 専用）
$ sudo e2fsck /dev/sdb1

# 対話なしで自動修復（-y = すべての質問に yes）
$ sudo e2fsck -y /dev/sdb1

# 強制チェック（クリーンでも実行）
$ sudo e2fsck -f /dev/sdb1

# 強制チェック + 自動修復（よく使う組み合わせ）
$ sudo e2fsck -fy /dev/sdb1

# 詳細表示（verbose）
$ sudo e2fsck -v /dev/sdb1

# バックアップスーパーブロックを使って修復
# バックアップの場所を確認
$ sudo dumpe2fs /dev/sdb1 | grep "superblock"
Primary superblock at 0, Group descriptors at 1-1
Backup superblock at 32768, Group descriptors at 32769-32769
Backup superblock at 98304, Group descriptors at 98305-98305

# バックアップスーパーブロックを指定して修復
$ sudo e2fsck -b 32768 /dev/sdb1

# /etc/fstab の全ファイルシステムをチェック
$ sudo fsck -A

# 起動時の自動チェック（次回起動時に強制チェック）
$ sudo tune2fs -C 99 /dev/sdb1   # マウント回数を最大値に設定
$ sudo shutdown -rF now           # -F：次回起動時に強制 fsck

fsck の終了コード

終了コード意味
0エラーなし
1ファイルシステムのエラーを修正した
2システムを再起動すべき
4未修正のファイルシステムエラーが残っている
8操作エラー
16使用方法・構文エラー
32ユーザーによるキャンセル
128共有ライブラリエラー
⚠️ fsck 実行時の注意事項
・必ずアンマウント状態で実行する（マウント中の実行はデータ破損の原因）
・ルートFS（/）のチェックは起動時のシングルユーザーモードまたは Live CD から行う
・-y オプションは自動修復するが、意図しない変更が行われる可能性がある
・重要なデータは事前にバックアップを取ること

④ S.M.A.R.T.（ディスク健全性監視）

重要ポイント③：S.M.A.R.T.（Self-Monitoring, Analysis and Reporting Technology）はHDD/SSDが自己診断する機能。smartctl コマンドで確認する
ディスク障害を事前に検知して、データ損失を防ぐために使用します。

⑤ XFS ファイルシステムの管理

# XFS のチェックと修復（アンマウント状態で実行）
$ sudo xfs_repair /dev/sdb1
Phase 1 - find and verify superblock...
Phase 2 - using internal log
Phase 3 - for each AG...
Phase 4 - check for duplicate blocks...
Phase 5 - rebuild AG headers and trees...
Phase 6 - check inode connectivity...
Phase 7 - verify and correct link counts...
done

# ドライラン（実際には修復しない）
$ sudo xfs_repair -n /dev/sdb1

# ログをクリアして修復（ログが壊れている場合）
$ sudo xfs_repair -L /dev/sdb1   # ⚠️ データ損失の可能性あり

# XFS の情報表示
$ xfs_info /dev/sdb1
$ xfs_info /mnt/xfsdata       # マウントポイントでも可

# XFS のラベル・UUID 操作
$ sudo xfs_admin -l /dev/sdb1          # ラベル表示
$ sudo xfs_admin -L "xfsdata" /dev/sdb1 # ラベル設定
$ sudo xfs_admin -u /dev/sdb1          # UUID 表示
$ sudo xfs_admin -U generate /dev/sdb1  # UUID 再生成

# XFS のオンライン拡張（マウント中でも可能）
$ sudo xfs_growfs /mnt/xfsdata
$ sudo xfs_growfs -D 2097152 /mnt/xfsdata  # サイズを指定（ブロック数）

# XFS のバックアップとリストア
$ sudo xfsdump -l 0 -f /backup/xfs.dump /mnt/xfsdata  # フルバックアップ
$ sudo xfsrestore -f /backup/xfs.dump /mnt/restore    # リストア

# XFS のデフラグ（マウント中に実行可能）
$ sudo xfs_fsr /mnt/xfsdata

# XFS のクォータ管理
$ sudo mount -o uquota /dev/sdb1 /mnt/xfsdata  # ユーザークォータ有効
$ xfs_quota -x -c 'report -u' /mnt/xfsdata

⑥ Btrfs ファイルシステムの管理

# Btrfs のチェックと修復
$ sudo btrfs check /dev/sdb1                  # 読み取り専用チェック
$ sudo btrfs check --repair /dev/sdb1         # 修復（⚠️ アンマウント必須）

# Btrfs の情報表示
$ sudo btrfs filesystem show /dev/sdb1
$ sudo btrfs filesystem df /mnt/btrfs          # 使用量表示
$ sudo btrfs filesystem usage /mnt/btrfs       # 詳細使用量

# サブボリュームの管理
$ sudo btrfs subvolume create /mnt/btrfs/data  # 作成
$ sudo btrfs subvolume list /mnt/btrfs          # 一覧
$ sudo btrfs subvolume delete /mnt/btrfs/data  # 削除

# スナップショットの作成
$ sudo btrfs subvolume snapshot \
    /mnt/btrfs/data \
    /mnt/btrfs/snapshots/data_$(date +%Y%m%d)
# 読み取り専用スナップショット
$ sudo btrfs subvolume snapshot -r \
    /mnt/btrfs/data \
    /mnt/btrfs/snapshots/data_ro

# Btrfs のスクラブ（データ整合性チェック）
$ sudo btrfs scrub start /mnt/btrfs            # スクラブ開始
$ sudo btrfs scrub status /mnt/btrfs           # 状態確認
$ sudo btrfs scrub cancel /mnt/btrfs           # キャンセル

# Btrfs のバランス（データ再配置）
$ sudo btrfs balance start /mnt/btrfs
$ sudo btrfs balance status /mnt/btrfs

# Btrfs の拡張（デバイス追加）
$ sudo btrfs device add /dev/sdc1 /mnt/btrfs
$ sudo btrfs filesystem resize max /mnt/btrfs

# Btrfs の圧縮を有効にしてマウント
$ sudo mount -o compress=zstd /dev/sdb1 /mnt/btrfs

⑦ オートマウント（autofs）

重要ポイント④：autofs はファイルシステムへのアクセスが発生したときに自動的にマウントし、一定時間アクセスがなければ自動的にアンマウントするデーモン
NFS・CD/DVD・USB などを必要なときだけマウントするために使用します。

autofs の設定ファイル構成

# autofs の設定ファイル構成
/etc/auto.master        # マスターマップ（メイン設定）
/etc/auto.master.d/     # マスターマップの追加設定ディレクトリ
/etc/auto.misc          # 直接マップファイルの例（misc）
/etc/auto.net           # NFS 自動検出マップ

# autofs のインストール
$ sudo apt install autofs

# autofs の起動
$ sudo systemctl enable --now autofs

/etc/auto.master（マスターマップ）

# /etc/auto.master の書式
# マウントポイント  マップファイル  [オプション]

# /etc/auto.master の例
/misc   /etc/auto.misc                    # misc マップを /misc に適用
/mnt    /etc/auto.mnt   --timeout=60      # タイムアウト60秒
/net    -hosts                             # NFS ホスト自動検出
/home   auto.home                          # ホームディレクトリ自動マウント

# オプション
# --timeout=N  : N秒後に自動アンマウント（デフォルト300秒）
# --ghost      : マウントポイントのディレクトリを常に表示
# --browse     : ブラウズ可能なマップ

マップファイルの種類と書式

## 直接マップ（/etc/auto.misc の例）
# 書式：キー  [オプション]  場所

# CD/DVD の自動マウント
cdrom   -fstype=iso9660,ro,nosuid,nodev  :/dev/sr0

# USB メモリの自動マウント
usb     -fstype=auto,rw,sync,nosuid      :/dev/sdb1

# NFS の自動マウント
nfsdata -fstype=nfs,rw                   fileserver:/exports/data

# アクセス方法
# /misc/cdrom  → /dev/sr0 が iso9660 でマウントされる
# /misc/usb    → /dev/sdb1 が自動検出でマウントされる
# /misc/nfsdata → fileserver:/exports/data が NFS でマウントされる

## 間接マップ（/etc/auto.mnt の例）
# auto.master に「/mnt  /etc/auto.mnt」と記述した場合
# /mnt/以下のディレクトリが自動マウントポイントになる

# NFS サーバーのマウント
data    -rw,soft  192.168.1.10:/exports/data
backup  -ro       192.168.1.10:/exports/backup
home    -rw       192.168.1.10:/home

# アクセス方法
# /mnt/data   → 192.168.1.10:/exports/data が NFS でマウント
# /mnt/backup → 192.168.1.10:/exports/backup が ro でマウント
# /mnt/home   → 192.168.1.10:/home が rw でマウント

## ワイルドカードマップ（ユーザーホームディレクトリの例）
# /etc/auto.home の内容
*   -rw,soft  192.168.1.10:/home/&
# & はキー（*）の値に置換される

# auto.master に「/home  /etc/auto.home」と記述した場合
# /home/teru にアクセス → 192.168.1.10:/home/teru がマウントされる
# /home/alice にアクセス → 192.168.1.10:/home/alice がマウントされる

## 設定変更の反映
$ sudo systemctl reload autofs
$ sudo automount -f   # フォアグラウンドで起動（デバッグ用）

## 動作確認
$ ls /misc/cdrom      # アクセスするとマウントされる
$ mount | grep autofs # マウント状態を確認

オートマウントの設定例（NFS ホームディレクトリ）

# NFS サーバーのホームディレクトリを自動マウントする設定例

## ステップ1：/etc/auto.master に追記
$ sudo vi /etc/auto.master
/home   /etc/auto.home  --timeout=300

## ステップ2：/etc/auto.home を作成
$ sudo vi /etc/auto.home
*   -rw,soft,intr  nfsserver:/home/&

## ステップ3：autofs を再起動
$ sudo systemctl restart autofs

## ステップ4：動作確認
# ユーザー teru のホームにアクセス
$ ls /home/teru
# → nfsserver:/home/teru が自動的にマウントされる

$ mount | grep home
nfsserver:/home/teru on /home/teru type nfs (rw,soft,intr,...)

# 5分間アクセスがないと自動的にアンマウントされる
✅ autofs の利点
・必要なときだけマウント：常時マウントより効率的（特に NFS）
・自動アンマウント：使用後は自動的に解放されリソースを節約
・NFS サーバーが停止中でも問題なし：アクセス時にのみ接続を試みる
・大規模環境に最適：多数のユーザーのホームディレクトリを効率的に管理
