① mkfs コマンドの概要

重要ポイント①：mkfs は各ファイルシステム作成コマンドのフロントエンド。mkfs -t ext4 と mkfs.ext4 は同じ動作をする
実際には mkfs.ext4・mkfs.xfs などの専用コマンドを直接呼び出すことが多いです。

② ext2 / ext3 / ext4 ファイルシステムの作成

重要ポイント②：mke2fs は ext2/3/4 を作成する共通コマンド。-t オプションでタイプを指定する。mkfs.ext4 は mke2fs -t ext4 の別名

mke2fs / mkfs.ext4 の使い方

# ext4 ファイルシステムを作成（最もよく使う）
$ sudo mkfs.ext4 /dev/sdb1
mke2fs 1.47.0 (5-Feb-2023)
Creating filesystem with 2621440 4k blocks and 655360 inodes
Filesystem UUID: xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Superblock backups stored on blocks:
        32768, 98304, 163840, ...
Allocating group tables: done
Writing inode tables: done
Creating journal (16384 blocks): done
Writing superblocks and filesystem accounting information: done

# mke2fs で同じ操作
$ sudo mke2fs -t ext4 /dev/sdb1

# ラベルを付けて作成
$ sudo mkfs.ext4 -L "mydata" /dev/sdb1

# ブロックサイズを指定（デフォルト4096）
$ sudo mkfs.ext4 -b 4096 /dev/sdb1

# root 用予約ブロックを 1% に変更（デフォルト5%）
$ sudo mkfs.ext4 -m 1 /dev/sdb1

# inode 数を指定（多数の小さいファイルを扱う場合）
$ sudo mkfs.ext4 -i 4096 /dev/sdb1   # 4096バイトごとに1 inode

# ext2 の作成（ジャーナリングなし）
$ sudo mkfs.ext2 /dev/sdb1
$ sudo mke2fs /dev/sdb1              # デフォルトは ext2

# ext3 の作成（ジャーナリングあり）
$ sudo mkfs.ext3 /dev/sdb1
$ sudo mke2fs -t ext3 /dev/sdb1

# ドライラン（実際には作成しない）
$ sudo mke2fs -n -t ext4 /dev/sdb1

tune2fs：ext2/3/4 の設定変更

# スーパーブロック情報を表示
$ sudo tune2fs -l /dev/sdb1
Filesystem volume name:   mydata
Last mounted on:          /data
Filesystem UUID:          xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx

Filesystem revision #:    1 (dynamic)
Filesystem features:      has_journal ext_attr resize_inode dir_index ...
Block count:              2621440

Free blocks:              2345678

# ラベルを変更
$ sudo tune2fs -L "newlabel" /dev/sdb1

# 予約ブロック率を変更
$ sudo tune2fs -m 1 /dev/sdb1

# マウント回数でのfsck間隔を設定（0=無効）
$ sudo tune2fs -c 0 /dev/sdb1

# ext2 に ext3 のジャーナルを追加（ext2→ext3 変換）
$ sudo tune2fs -j /dev/sdb1

# UUID を新たに生成
$ sudo tune2fs -U random /dev/sdb1

ext2 / ext3 / ext4 の違い

特徴ext2ext3ext4

③ XFS ファイルシステムの作成

# XFS ファイルシステムを作成
$ sudo mkfs.xfs /dev/sdb1
meta-data=/dev/sdb1              isize=512    agcount=4, agsize=655360 blks
         =                       sectsz=512   attr=2, projid32bit=1
         =                       crc=1        finobt=1, sparse=1, rmapbt=0
data     =                       bsize=4096   blocks=2621440, imaxpct=25
         =                       sunit=0      swidth=0 blks
naming   =version 2              bsize=4096   ascii-ci=0, ftype=1
log      =internal log           bsize=4096   blocks=2560, version=2
realtime =none                   extsz=4096   blocks=0, rtextents=0

# ラベルを付けて作成
$ sudo mkfs.xfs -L "xfsdata" /dev/sdb1

# 既存の FS を強制上書き
$ sudo mkfs.xfs -f /dev/sdb1

# ブロックサイズを指定
$ sudo mkfs.xfs -b size=4096 /dev/sdb1

# XFS の情報表示
$ xfs_info /dev/sdb1
$ xfs_info /mnt/xfsdata   # マウント後はマウントポイントでも可

# XFS ラベルの変更（マウント中でも可能）
$ sudo xfs_admin -L "newlabel" /dev/sdb1

# XFS UUID の変更
$ sudo xfs_admin -U generate /dev/sdb1

# XFS ファイルシステムの拡張（マウント中でも可能）
$ sudo xfs_growfs /mnt/xfsdata
⚠️ XFS の重要な制限
・XFS は縮小できません（拡張のみ可能）
・xfs_repair はアンマウント状態で実行する必要があります
・xfsdump / xfsrestore でバックアップ・リストアを行います

⑥ CD/DVD の作成

重要ポイント③：mkisofs（またはgenisoimage）でISOイメージを作成し、cdrecord（またはwodim）でCD/DVDに書き込む

ISO イメージの作成と書き込み（タブで切り替え）

mkisofs / genisoimage による ISO イメージ作成

# 基本的な ISO イメージの作成
$ mkisofs -o output.iso /path/to/source/

# genisoimage（mkisofs の後継・互換コマンド）
$ genisoimage -o output.iso /path/to/source/

# ボリュームラベルを付けて作成
$ mkisofs -o output.iso -V "MY_DISC" /path/to/source/

# Rock Ridge 拡張（Linux のパーミッション・シンボリックリンクを保持）
$ mkisofs -o output.iso -R /path/to/source/

# Joliet 拡張（Windows の長いファイル名に対応）
$ mkisofs -o output.iso -J /path/to/source/

# Rock Ridge + Joliet（両方に対応）
$ mkisofs -o output.iso -R -J -V "MY_DISC" /path/to/source/

# ブータブル ISO の作成（ISOLINUX を使用）
$ mkisofs -o bootable.iso \
    -b isolinux/isolinux.bin \
    -c isolinux/boot.cat \
    -no-emul-boot \
    -boot-load-size 4 \
    -boot-info-table \
    -R -J -V "BOOTDISC" \
    /path/to/source/

# ISO イメージをループマウントして確認
$ sudo mount -o loop output.iso /mnt/iso
$ ls /mnt/iso
$ sudo umount /mnt/iso

mkisofs の主要オプション

オプション説明
-o ファイル名出力 ISO ファイル名を指定
-V ラベルボリュームラベルを設定（最大32文字）
-RRock Ridge 拡張（Linux パーミッション保持）
-JJoliet 拡張（Windows 長いファイル名対応）
-rRock Ridge（パーミッションをリセット）
-b ファイルブートイメージファイルを指定
-c ファイルブートカタログファイルを指定
-no-emul-bootディスクエミュレーションなしで起動
-boot-load-size Nブートセクタのロードサイズ
-boot-info-tableブート情報テーブルを ISO に埋め込む
-fシンボリックリンクをたどる
-l31文字を超えるファイル名を許可

cdrecord / wodim による CD/DVD 書き込み

# cdrecord（Debian/Ubuntu では wodim が代替）
# インストール
$ sudo apt install wodim cdrecord

# 書き込みデバイスの確認
$ cdrecord --devices
$ wodim --devices
wodim: Overview of accessible drives (1 found) :
-------------------------------------------------------------------------
 0  dev='/dev/sr0'    rwrw-- : 'ASUS' 'DRW-24D5MT'

# ISO イメージを CD に書き込む
$ cdrecord -v dev=/dev/sr0 output.iso
$ wodim -v dev=/dev/sr0 output.iso

# 書き込み速度を指定
$ cdrecord -v speed=8 dev=/dev/sr0 output.iso

# DVD に書き込む（growisofs を使用）
$ sudo apt install dvd+rw-tools
$ growisofs -dvd-compat -Z /dev/sr0=output.iso

# CD-RW を消去してから書き込む
$ cdrecord -v blank=fast dev=/dev/sr0
$ cdrecord -v dev=/dev/sr0 output.iso

# CD の内容を ISO イメージとして読み込む
$ dd if=/dev/sr0 of=backup.iso bs=2048

⑦ 暗号化ファイルシステムの作成（LUKS）

重要ポイント④：LUKS（Linux Unified Key Setup）は Linux 標準の暗号化方式。cryptsetup コマンドで管理する
パーティション全体を暗号化し、正しいパスフレーズを入力しないとデータにアクセスできません。

LUKS の仕組み

【LUKS の構造】
/dev/sdb1 → LUKS ヘッダー（暗号化キー・メタデータ） + 暗号化されたデータ領域
↓ cryptsetup luksOpen（パスフレーズ入力）
/dev/mapper/mydata → 復号化された仮想デバイス（通常のデバイスとして使用可能）
↓ mkfs.ext4 / mount
/mnt/encrypted → 通常のファイルシステムとしてアクセス可能

LUKS 暗号化ファイルシステムの作成手順

1

🔐 LUKS コンテナの作成（フォーマット）

パーティションを LUKS コンテナとして初期化する

2

🔓 LUKS コンテナを開く（マッピング）

パスフレーズを入力して /dev/mapper/ に仮想デバイスを作成

3

🔨 ファイルシステムの作成

仮想デバイスに通常のファイルシステムを作成

4

📁 マウントして使用

通常のファイルシステムと同様にマウントして使用

5

🔒 使用後はアンマウントして閉じる

umount → cryptsetup luksClose でデータを保護

# cryptsetup のインストール
$ sudo apt install cryptsetup

## ステップ1：LUKS コンテナの作成（フォーマット）
$ sudo cryptsetup luksFormat /dev/sdb1
WARNING!
========
This will overwrite data on /dev/sdb1 irrevocably.
Are you sure? (Type 'yes' in capital letters): YES
Enter passphrase for /dev/sdb1: 
Verify passphrase: 

# 暗号化アルゴリズムを指定して作成（デフォルト：aes-xts-plain64）
$ sudo cryptsetup luksFormat --cipher aes-xts-plain64 \
    --key-size 512 --hash sha512 /dev/sdb1

## ステップ2：LUKS コンテナを開く
$ sudo cryptsetup luksOpen /dev/sdb1 mydata
#                              ↑デバイス  ↑マッピング名（任意）
Enter passphrase for /dev/sdb1: 

# 仮想デバイスが作成されたことを確認
$ ls /dev/mapper/
control  mydata

## ステップ3：ファイルシステムの作成
$ sudo mkfs.ext4 /dev/mapper/mydata

## ステップ4：マウントして使用
$ sudo mkdir /mnt/encrypted
$ sudo mount /dev/mapper/mydata /mnt/encrypted
$ df -h /mnt/encrypted

## ステップ5：使用後はアンマウントして閉じる
$ sudo umount /mnt/encrypted
$ sudo cryptsetup luksClose mydata
# または
$ sudo cryptsetup close mydata

LUKS の管理コマンド

# LUKS ヘッダー情報を表示
$ sudo cryptsetup luksDump /dev/sdb1
LUKS header information for /dev/sdb1
Version:        2
Epoch:          3
Metadata area:  16384 [bytes]
Keyslots area:  16744448 [bytes]
UUID:           xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx
Label:          (no label)
Subsystem:      (no subsystem)
Flags:          (no flags)

# LUKS デバイスかどうか確認
$ sudo cryptsetup isLuks /dev/sdb1 && echo "LUKS device"

# パスフレーズを追加（最大8つのキースロット）
$ sudo cryptsetup luksAddKey /dev/sdb1

# パスフレーズを削除
$ sudo cryptsetup luksRemoveKey /dev/sdb1

# キーファイルを使った暗号化（パスフレーズの代わり）
$ sudo dd if=/dev/urandom of=/root/keyfile bs=4096 count=1
$ sudo chmod 400 /root/keyfile
$ sudo cryptsetup luksAddKey /dev/sdb1 /root/keyfile
$ sudo cryptsetup luksOpen /dev/sdb1 mydata --key-file /root/keyfile

# /etc/crypttab で起動時の自動マッピング設定
# 書式：名前  デバイス  キーファイル  オプション
$ cat /etc/crypttab
mydata  UUID=xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx  none  luks
mydata2 /dev/sdb2  /root/keyfile  luks
