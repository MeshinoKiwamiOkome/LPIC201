① ネットワーク関連ファイル

重要ポイント①：Linux のネットワーク設定は複数の設定ファイルで管理される。各ファイルの役割と書式を正確に理解することが重要

主要なネットワーク関連ファイル（クリックで詳細）

システムのホスト名を設定する

ネットワーク名と IP アドレスのマッピング

# /etc/nsswitch.conf の hosts 行の設定例

# 標準的な設定（/etc/hosts → DNS）
hosts:      files dns

# mDNS を含む設定（Ubuntu のデフォルト）
hosts:      files mdns4_minimal [NOTFOUND=return] dns myhostname

# NIS を使用する場合
hosts:      files nis dns

# サービスの意味
# files        : /etc/hosts を参照
# dns          : /etc/resolv.conf の DNS サーバーに問い合わせ
# nis          : NIS（Yellow Pages）サーバーに問い合わせ
# mdns4_minimal: mDNS（Avahi）で .local ドメインを解決
# myhostname   : 自ホスト名を解決

# アクションの意味（[STATUS=ACTION]）
# [NOTFOUND=return]  : 見つからなければ次のサービスを試さず終了
# [NOTFOUND=continue]: 見つからなければ次のサービスを試す（デフォルト）
# [SUCCESS=return]   : 成功したら終了
# [UNAVAIL=continue] : サービスが利用不可なら次を試す

③ /etc/resolv.conf の詳細

# /etc/resolv.conf の完全な設定例

# DNS サーバーを最大3つ指定
nameserver 192.168.1.1     # プライマリ DNS
nameserver 8.8.8.8         # セカンダリ DNS
nameserver 8.8.4.4         # ターシャリ DNS

# 短縮名の検索ドメインリスト
search example.com local.example.com
# → "webserver" を解決する際に以下を順番に試みる
#   webserver.example.com → webserver.local.example.com

# ローカルドメイン（search の代替、どちらか一方のみ有効）
# domain example.com

# オプション設定
options ndots:5     # ドットが5個未満の場合に search を適用
options timeout:2   # タイムアウト秒数
options attempts:3  # リトライ回数
options rotate      # nameserver をラウンドロビンで使用

# systemd-resolved との連携確認
$ ls -la /etc/resolv.conf
lrwxrwxrwx 1 root root 39 /etc/resolv.conf -> ../run/systemd/resolve/stub-resolv.conf
# シンボリックリンクの場合は systemd-resolved が管理している

# systemd-resolved の設定確認
$ resolvectl status
$ resolvectl dns

search と domain の違い

ディレクティブ説明例
search 複数のドメインを指定可能。短縮名解決時に順番に試みる search example.com sub.example.com
domain 1つのドメインのみ指定。search の代替（両方書いた場合は後者が有効） domain example.com

④ ネットワークの問題解決

重要ポイント②：ネットワーク問題は「物理層→IP層→名前解決→アプリケーション層」の順に確認する。問題を切り分けることが重要

問題解決の手順（クリックで詳細コマンドを表示）

1

🔌 インターフェースの確認

NIC が認識されているか・IP アドレスが設定されているか確認

2

🏠 ローカル疎通確認

ループバック・同一セグメントのホストへの疎通を確認

3

🔀 デフォルトゲートウェイの確認

ゲートウェイへの疎通・ルーティングテーブルを確認

4

🌐 外部疎通確認

インターネット（IP アドレス直接指定）への疎通を確認

5

🔤 名前解決の確認

DNS による名前解決が正常に動作しているか確認

6

🚪 ポート・サービスの確認

目的のポートが開いているか・サービスが動作しているか確認

⑤ 名前解決の確認コマンド

dig・nslookup・host コマンド

## dig コマンド（最も詳細・推奨）

# 基本的な名前解決
$ dig google.com
;; ANSWER SECTION:
google.com.             300     IN      A       142.250.196.78

# 特定の DNS サーバーに問い合わせ
$ dig @8.8.8.8 google.com

# レコードタイプを指定
$ dig google.com MX      # メールサーバー
$ dig google.com NS      # ネームサーバー
$ dig google.com AAAA    # IPv6 アドレス
$ dig google.com TXT     # TXT レコード
$ dig google.com ANY     # すべてのレコード

# 逆引き（IP → ホスト名）
$ dig -x 8.8.8.8
8.8.8.8.in-addr.arpa.  21599 IN PTR dns.google.

# 簡潔な出力（+short）
$ dig google.com +short
142.250.196.78

# トレース（ルートから順に解決過程を表示）
$ dig google.com +trace

## nslookup コマンド（対話式・Windows との互換性）
$ nslookup google.com
Server:         127.0.0.53
Address:        127.0.0.53#53
Non-authoritative answer:
Name:   google.com
Address: 142.250.196.78

# 特定の DNS サーバーに問い合わせ
$ nslookup google.com 8.8.8.8

# 逆引き
$ nslookup 8.8.8.8

## host コマンド（シンプル）
$ host google.com
google.com has address 142.250.196.78
google.com has IPv6 address 2404:6800:4004:81d::200e
google.com mail is handled by 10 smtp.google.com.

# 逆引き
$ host 8.8.8.8
8.8.8.8.in-addr.arpa domain name pointer dns.google.

名前解決のトラブルシューティング（インタラクティブ）

名前解決コマンドの比較

コマンド特徴主な用途
dig最も詳細な情報・スクリプト向きDNS の詳細調査・トラブルシューティング
nslookup対話式・Windows との互換性簡易的な名前解決確認
hostシンプルな出力素早い名前解決確認
resolvectlsystemd-resolved の管理systemd 環境での DNS 設定確認
getent hostsnsswitch.conf の設定を使用実際の名前解決順序での確認
 
# getent：nsswitch.conf の設定通りに名前解決を確認
$ getent hosts google.com
142.250.196.78  google.com

# /etc/hosts に登録されたホストも解決できる
$ getent hosts webserver
192.168.1.10    webserver.local webserver

# hostname コマンド
$ hostname                  # 現在のホスト名を表示
$ hostname -f              # FQDN を表示
$ hostname -i              # ホストの IP アドレスを表示
$ hostname -I              # すべての IP アドレスを表示
$ sudo hostname newname    # ホスト名を一時的に変更

# hostnamectl（systemd 環境）
$ hostnamectl status
   Static hostname: myserver
   Pretty hostname: My Server
         Icon name: computer-laptop
           Chassis: laptop
        Machine ID: xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
           Boot ID: yyyyyyyyyyyyyyyyyyyyyyyyyyyyyyyy
  Operating System: Ubuntu 24.04 LTS
            Kernel: Linux 6.8.0-51-generic
$ sudo hostnamectl set-hostname newserver
