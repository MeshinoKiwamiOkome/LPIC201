① カーネルとは

重要ポイント①：カーネルはOSの中核であり、ハードウェアとアプリケーションの橋渡しをする
ユーザーが直接ハードウェアを操作することはできません。 すべてのハードウェアアクセスはカーネルを経由して行われます。

Linuxカーネルのアーキテクチャ（クリックで詳細表示）

👤 ユーザー空間（User Space）
シェル・アプリケーション・ライブラリ（glibc）
↕ システムコール（System Call Interface）
🔗 システムコールインターフェース
read / write / open / fork / exec ...
↕
⚙️ カーネル空間（Kernel Space）
プロセス管理 ／ メモリ管理 ／ ファイルシステム ／ ネットワーク ／ IPC
↕
🔌 デバイスドライバ
ディスク・NIC・USB・GPU・キーボード...
↕
🖥️ ハードウェア（Hardware）
CPU ／ RAM ／ ストレージ ／ ネットワーク機器

② カーネルバージョン

重要ポイント②：Linuxカーネルのバージョン番号は「メジャー.マイナー.パッチレベル」の形式で表される
バージョン番号の各部分が何を意味するかを正確に理解することが重要です。

バージョン番号の確認

# カーネルバージョンを確認する主なコマンド

# uname コマンド（最もよく使う）
$ uname -r
6.8.0-51-generic

# すべての情報を表示
$ uname -a
Linux teru-LetsNote 6.8.0-51-generic #52-Ubuntu SMP PREEMPT_DYNAMIC Thu Dec  5 13:09:44 UTC 2024 x86_64 x86_64 x86_64 GNU/Linux

# /proc/version からも確認可能
$ cat /proc/version
Linux version 6.8.0-51-generic (buildd@lcy02-amd64-032) (gcc version 13.2.0 ...) #52-Ubuntu SMP ...

# インストール済みカーネル一覧
$ dpkg --list | grep linux-image
ii  linux-image-6.8.0-51-generic  6.8.0-51.52  amd64  Signed kernel image generic

③ カーネルイメージ

重要ポイント③：カーネルイメージとはカーネル本体の実行ファイルであり、/boot ディレクトリに配置される
システム起動時にブートローダ（GRUBなど）がカーネルイメージを読み込んでメモリに展開します。

/boot ディレクトリの構成

$ ls -lh /boot/
total 156M
-rw-r--r-- 1 root root  286K vmlinuz-6.8.0-51-generic   # カーネルイメージ（圧縮済み）
-rw-r--r-- 1 root root   84M initrd.img-6.8.0-51-generic  # 初期RAMディスク
-rw-r--r-- 1 root root  7.7M System.map-6.8.0-51-generic  # カーネルシンボルテーブル
-rw-r--r-- 1 root root  287K config-6.8.0-51-generic      # カーネルビルド設定
drwxr-xr-x 6 root root  4.0K grub/                        # GRUBブートローダ設定
lrwxrwxrwx 1 root root    27 vmlinuz -> vmlinuz-6.8.0-51-generic
lrwxrwxrwx 1 root root    32 initrd.img -> initrd.img-6.8.0-51-generic

/boot の主要ファイル（クリックで詳細表示）

vmlinuz-<version>
圧縮されたカーネルイメージ本体。ブートローダが最初に読み込むファイル
initrd.img-<version>
初期RAMディスク。カーネル起動直後に使用する一時的なルートファイルシステム
System.map-<version>
カーネルのシンボルテーブル。デバッグやカーネルクラッシュ解析に使用
config-<version>
カーネルのビルド設定ファイル。どの機能が有効化されているかを記録
grub/
GRUBブートローダの設定ディレクトリ。grub.cfgが起動メニューを定義
vmlinuz（シンボリックリンク）
最新カーネルへのシンボリックリンク。常に最新バージョンを指す

カーネルイメージの種類と特徴

ファイル名説明主な用途
vmlinuz 圧縮カーネルイメージ（bzImage形式） x86/x86_64系の標準カーネル
vmlinux 非圧縮カーネルイメージ（ELF形式） デバッグ・カーネル解析用（通常は/bootに置かない）
bzImage big zImage。vmlinuzの実体 x86系の標準圧縮形式
zImage 古い圧縮形式（512KB以下） 古いx86システム・組み込み系
Image 非圧縮イメージ ARM系（Raspberry Piなど）
uImage U-Boot用カーネルイメージ 組み込みLinux（U-Bootブートローダ使用時）

④ カーネルの種類

モノリシックカーネル vs マイクロカーネル

種類特徴代表例長所短所
モノリシックカーネル OS機能すべてをカーネル空間で実行 Linux・FreeBSD 高速・効率的 一部の障害が全体に影響
マイクロカーネル 最小限の機能のみカーネル空間で実行 Mach・MINIX・QNX 安定性・移植性が高い オーバーヘッドが大きい
ハイブリッドカーネル 両者の折衷案 Windows NT・macOS（XNU） バランスが良い 複雑
✅ Linuxはモノリシックカーネルだが、カーネルモジュールで動的拡張が可能
純粋なモノリシックカーネルと異なり、Linuxはカーネルモジュール（.koファイル）を 実行中に動的にロード・アンロードできます。これにより、モノリシックの高速性と マイクロカーネルの柔軟性を両立しています。

カーネルのコンパイルオプション（config-* の設定値）

# カーネル設定の確認
$ grep CONFIG_EXT4 /boot/config-$(uname -r)
CONFIG_EXT4_FS=y           # y：カーネルに静的組み込み
CONFIG_EXT4_USE_FOR_EXT2=y

$ grep CONFIG_USB /boot/config-$(uname -r)
CONFIG_USB=m               # m：カーネルモジュールとして利用可能
CONFIG_USB_STORAGE=m

$ grep CONFIG_SOUND /boot/config-$(uname -r)
# CONFIG_SOUND is not set  # 無効化されている

# 実行中カーネルの設定を確認（/proc/config.gz）
$ zcat /proc/config.gz | grep CONFIG_EXT4

⑤ カーネル関連の重要ディレクトリ

パス内容
/boot/ カーネルイメージ・initramfs・GRUBなどのブート関連ファイル
/proc/ カーネルが提供する仮想ファイルシステム。実行中カーネルの状態をファイルとして参照できる
/proc/version カーネルバージョン情報
/proc/cmdline カーネル起動時に渡されたパラメータ
/proc/modules 現在ロードされているカーネルモジュール一覧
/proc/kallsyms 実行中カーネルのシンボルテーブル
/sys/ sysfs。デバイス・ドライバ・カーネルサブシステムの情報を提供する仮想FS
/lib/modules/<version>/ カーネルモジュール（.koファイル）の格納ディレクトリ
/usr/src/linux-headers-<version>/ カーネルヘッダファイル（モジュールのコンパイルに必要） 
# /proc の主要ファイルを確認
$ cat /proc/version
Linux version 6.8.0-51-generic ...

$ cat /proc/cmdline
BOOT_IMAGE=/boot/vmlinuz-6.8.0-51-generic root=UUID=xxxx-xxxx ro quiet splash

$ ls /lib/modules/$(uname -r)/
build  kernel  modules.alias  modules.dep  modules.symbols ...

# カーネルモジュールの格納場所
$ ls /lib/modules/$(uname -r)/kernel/
arch/  crypto/  drivers/  fs/  lib/  net/  sound/ ...
