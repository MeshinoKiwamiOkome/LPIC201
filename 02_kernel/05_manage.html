/proc 仮想ファイルシステムの確認

重要ポイント①：/proc はカーネルが提供する仮想ファイルシステムで、実行中のカーネルやプロセスの情報をファイルとして参照できる
ディスク上には存在せず、カーネルがアクセス時に動的に内容を生成します。 読み取り専用のファイルがほとんどですが、一部は書き込みによる設定変更も可能です。

/proc の主要ファイル・ディレクトリ（クリックで詳細）

/proc/
├── version ← カーネルバージョン・ビルド情報
├── cmdline ← カーネル起動パラメータ
├── cpuinfo ← CPU情報（モデル・コア数・フラグ）
├── meminfo ← メモリ使用状況の詳細
├── loadavg ← ロードアベレージ・プロセス数
├── uptime ← 稼働時間・アイドル時間（秒）
├── modules ← ロード済みカーネルモジュール（lsmod の元データ）
├── mounts ← マウント中のファイルシステム一覧
├── partitions ← 認識されているディスクパーティション
├── devices ← 登録済みデバイスとメジャー番号
├── interrupts ← IRQ（割り込み）の使用状況
├── net/ ← ネットワーク統計情報
├── sys/ ← カーネルパラメータ（sysctl の実体）
└── PID番号/ ← プロセスごとの情報ディレクトリ
    ├── cmdline ← プロセスの起動コマンド
    ├── status ← プロセスの状態・メモリ使用量
    ├── fd/ ← オープン中のファイルディスクリプタ
    └── maps ← メモリマップ

主要な /proc ファイルの活用例

# カーネルバージョン確認
$ cat /proc/version

# CPUコア数（スレッド数）を取得
$ grep -c processor /proc/cpuinfo
8

# 利用可能なメモリ量を確認（MemAvailable が実際に使えるメモリ）
$ grep MemAvailable /proc/meminfo
MemAvailable:    3276800 kB

# 特定プロセスの起動コマンドを確認
$ cat /proc/1/cmdline | tr '\0' ' '
/sbin/init splash

# プロセスがオープンしているファイルを確認
$ ls -la /proc/$$/fd
lrwx------ 1 teru teru 64 Jan  1 10:00 0 -> /dev/pts/0
lrwx------ 1 teru teru 64 Jan  1 10:00 1 -> /dev/pts/0
lrwx------ 1 teru teru 64 Jan  1 10:00 2 -> /dev/pts/0

# ネットワークインターフェースの統計
$ cat /proc/net/dev
Inter-|   Receive                                                |  Transmit
 face |bytes    packets errs drop fifo frame compressed multicast|bytes    packets
    lo: 1234567    9876    0    0    0     0          0         0   1234567    9876
  eth0: 9876543   54321    0    0    0     0          0         0   5432109   43210

# dmesg でカーネルメッセージを確認（問題解決に重要）
$ dmesg | tail -20
$ dmesg | grep -i error
$ dmesg -T          # タイムスタンプを人間が読みやすい形式で表示
$ dmesg -w          # リアルタイムで新しいメッセージを表示（tail -f 相当）

② デバイスファイル

重要ポイント②：デバイスファイルはハードウェアをファイルとして抽象化したもので、/dev/ ディレクトリに配置される
Linuxの「すべてはファイルである」という設計思想の中核をなします。 デバイスファイルにはブロックデバイス・キャラクタデバイス・疑似デバイスの3種類があります。

デバイスファイルの種類（クリックで詳細）

ブロックデバイス（b）
HDD / SSD / NVMe
/dev/sda, /dev/nvme0n1, /dev/vda
ランダムアクセス可能・バッファリングあり
キャラクタデバイス（c）
端末 / シリアル / キーボード
/dev/tty, /dev/ttyS0, /dev/input/event0
順次アクセス・バッファリングなし
疑似デバイス
null / zero / random / urandom
/dev/null, /dev/zero, /dev/random
物理デバイスを持たない特殊なデバイス

デバイスファイルの確認と操作

# /dev/ の主要デバイスを確認
$ ls -l /dev/ | head -20
total 0
brw-rw----  1 root disk      8,   0 Jan  1 10:00 sda    # b=ブロック
brw-rw----  1 root disk      8,   1 Jan  1 10:00 sda1
crw-rw-rw-  1 root tty       5,   0 Jan  1 10:00 tty    # c=キャラクタ
crw-rw-rw-  1 root root      1,   3 Jan  1 10:00 null
crw-rw-rw-  1 root root      1,   5 Jan  1 10:00 zero
# ↑先頭文字：b=ブロック c=キャラクタ
# ↑「8, 0」= メジャー番号8（SCSI/SATAディスク）, マイナー番号0（ディスク全体）

# メジャー番号・マイナー番号の確認
$ ls -l /dev/sda /dev/sda1 /dev/sda2
brw-rw---- 1 root disk 8, 0 /dev/sda   # メジャー8 マイナー0
brw-rw---- 1 root disk 8, 1 /dev/sda1  # メジャー8 マイナー1
brw-rw---- 1 root disk 8, 2 /dev/sda2  # メジャー8 マイナー2

# デバイスファイルを手動作成（mknod）
$ sudo mknod /dev/mydev c 89 0
#           ↑パス     ↑種類 ↑メジャー ↑マイナー
# c=キャラクタ b=ブロック p=名前付きパイプ

# 疑似デバイスの活用例
$ echo "不要な出力" > /dev/null        # 出力を捨てる
$ dd if=/dev/zero of=/tmp/test.img bs=1M count=100  # 100MBのゼロ埋めファイル作成
$ dd if=/dev/urandom of=/tmp/random.bin bs=1M count=1  # 1MBのランダムデータ

③ udev

重要ポイント③：udev はデバイスの接続・切断を検知して /dev/ 以下のデバイスファイルを動的に管理するデーモン
カーネルからの uevent（デバイスイベント）を受け取り、 ルールファイルに従ってデバイスファイルの作成・削除・権限設定・シンボリックリンク作成などを行います。

udev の設定ファイル

# udev ルールファイルの場所
/etc/udev/rules.d/       # ユーザー定義ルール（優先度高）
/usr/lib/udev/rules.d/   # システム提供ルール
/run/udev/rules.d/       # 実行時に生成されるルール

# ルールファイルの命名規則
# 数字が小さいほど先に処理される（辞書順）
10-dm.rules
50-udev-default.rules
60-persistent-storage.rules
70-snap.rules
99-custom.rules   # ← ユーザー定義は99番台が慣習

# ルールファイルの例（/etc/udev/rules.d/99-custom.rules）
# USBストレージデバイスに固定名を付ける
SUBSYSTEM=="block", KERNEL=="sd*", ATTRS{idVendor}=="0781", ATTRS{idProduct}=="5567", SYMLINK+="myusb"

# シリアルポートのパーミッションを変更
KERNEL=="ttyUSB*", MODE="0666", GROUP="dialout"

# デバイス接続時にスクリプトを実行
SUBSYSTEM=="usb", ACTION=="add", RUN+="/usr/local/bin/usb-notify.sh"

udev ルールの主要キーワード

キーワード種類説明例
ACTIONマッチイベントの種類ACTION=="add" / "remove"
KERNELマッチカーネルデバイス名KERNEL=="sda*"
SUBSYSTEMマッチデバイスのサブシステムSUBSYSTEM=="block"
ATTRS{属性}マッチデバイスの属性値ATTRS{idVendor}=="0781"
NAME代入デバイスファイル名を設定NAME="mydev"
SYMLINK+代入シンボリックリンクを追加SYMLINK+="disk/myusb"
MODE代入デバイスファイルのパーミッションMODE="0666"
OWNER代入デバイスファイルの所有者OWNER="teru"
GROUP代入デバイスファイルのグループGROUP="dialout"
RUN+代入イベント時に実行するコマンドRUN+="/usr/bin/notify.sh"

udevadm コマンド

# デバイスの詳細情報を表示
$ udevadm info --query=all --name=/dev/sda
P: /devices/pci0000:00/0000:00:1f.2/ata1/host0/target0:0:0/0:0:0:0/block/sda
N: sda
S: disk/by-id/ata-SAMSUNG_SSD_860_EVO_1TB_xxxxxxxx
S: disk/by-path/pci-0000:00:1f.2-ata-1
E: DEVNAME=/dev/sda
E: DEVTYPE=disk
E: ID_BUS=ata
E: ID_MODEL=SAMSUNG_SSD_860_EVO_1TB

# デバイスの属性ツリーを表示（ルール作成時に参照）
$ udevadm info --attribute-walk --name=/dev/sda

# udev イベントをリアルタイムで監視
$ udevadm monitor
monitor will print the received events for:
UDEV - the event which udev sends out after rule processing
KERNEL - the kernel uevent
# USBデバイスを接続すると以下のようなイベントが表示される
KERNEL[12345.678] add /devices/pci0000:00/.../usb1/1-1 (usb)
UDEV  [12345.890] add /devices/pci0000:00/.../usb1/1-1 (usb)

# ルールファイルを再読み込み（udevd の再起動なしに反映）
$ sudo udevadm control --reload-rules

# ルールを再適用（既存デバイスに新しいルールを適用）
$ sudo udevadm trigger

# 特定デバイスにルールをテスト適用（実際には変更しない）
$ udevadm test /sys/block/sda
