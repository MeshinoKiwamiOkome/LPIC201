① なぜカーネルをコンパイルするのか

重要ポイント①：カスタムカーネルのコンパイルは、特定ハードウェア対応・機能の追加・削除・パフォーマンス最適化のために行う
現代のディストリビューションでは通常は不要ですが、 LPIC-201の試験範囲として手順の理解が求められます。

カーネルコンパイルが必要なケース

ケース説明
新しいハードウェアのサポート ディストリビューションのカーネルに含まれていないドライバが必要な場合
機能の追加・削除 特定の機能を有効化・無効化してシステムを最適化する場合
パフォーマンスチューニング 特定のCPUアーキテクチャに最適化したカーネルを作成する場合
セキュリティパッチの適用 公式リリース前のセキュリティパッチを適用したカーネルが必要な場合
組み込みシステム リソースが限られた組み込み環境向けに最小構成のカーネルを作成する場合

③ 事前準備

必要パッケージのインストール

# Debian / Ubuntu 系
$ sudo apt update
$ sudo apt install \
    build-essential \   # gcc, make, libc-dev など
    libncurses-dev \    # menuconfig の表示に必要
    libssl-dev \        # SSL関連
    libelf-dev \        # ELFファイル処理
    bison flex \        # パーサジェネレータ
    bc \                # 計算ツール（Makefile内で使用）
    dwarves \           # BTF（BPF Type Format）生成
    zstd                # zstd圧縮（モジュール圧縮に使用）

# RHEL / CentOS / AlmaLinux 系
$ sudo dnf install \
    gcc make ncurses-devel \
    openssl-devel elfutils-libelf-devel \
    bison flex bc dwarves

カーネルソースの取得と展開

# kernel.org から最新の安定版をダウンロード
$ wget https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.8.tar.xz

# /usr/src/ に展開（慣習的な配置場所）
$ sudo tar -xf linux-6.8.tar.xz -C /usr/src/

# ソースディレクトリに移動
$ cd /usr/src/linux-6.8/

# ディレクトリ構造の確認
$ ls
arch/  block/  crypto/  Documentation/  drivers/  fs/
include/  init/  ipc/  kernel/  lib/  mm/  net/  scripts/
security/  sound/  tools/  usr/  virt/  Makefile  Kconfig ...

# ソースツリーのクリーンアップ（再ビルド時）
$ make mrproper   # 設定ファイルを含むすべての生成ファイルを削除
$ make clean      # 生成ファイルのみ削除（.config は保持）
✅ ソースディレクトリの慣習
カーネルソースは /usr/src/linux-<version>/ に展開するのが慣習です。
また /usr/src/linux というシンボリックリンクで最新ソースを指すことも多いです。
sudo ln -s /usr/src/linux-6.8 /usr/src/linux

④ カーネルの設定（.config の生成）

重要ポイント②：カーネルの設定は .config ファイルで管理され、make menuconfig などのツールで生成・編集する
設定値は y（静的組み込み）・m（モジュール）・n（無効）の3種類です。

設定ツール一覧（クリックで詳細表示）

make menuconfig
ncursesベースのTUIメニュー。ターミナルで使える最も一般的な設定ツール
make xconfig
Qt/X11ベースのGUIツール。グラフィカルな設定画面（要X環境）
make gconfig
GTK+ベースのGUIツール。GNOMEデスクトップ環境向け（要X環境）
make oldconfig
既存の .config を元に新しいオプションのみ対話的に設定する
make defconfig
アーキテクチャのデフォルト設定で .config を生成する
make localmodconfig
現在ロードされているモジュールのみ有効にした最小設定を生成する

現在のカーネル設定を流用する（推奨）

# 現在実行中のカーネルの設定を .config としてコピー
$ cp /boot/config-$(uname -r) /usr/src/linux-6.8/.config

# または /proc/config.gz から取得（カーネルにCONFIG_IKCONFIG=yが必要）
$ zcat /proc/config.gz > /usr/src/linux-6.8/.config

# 新しいカーネルバージョンで追加されたオプションをデフォルト値で設定
$ cd /usr/src/linux-6.8/
$ make olddefconfig

# 必要に応じて menuconfig で追加設定
$ make menuconfig

.config の設定値の意味

設定値を選択して意味を確認しましょう

⑤ コンパイル

重要ポイント③：make コマンドでカーネルイメージとモジュールをコンパイルする。-j オプションで並列ビルドを指定できる
CPUコア数に合わせた並列ビルドにより、コンパイル時間を大幅に短縮できます。

コンパイルコマンド

# ソースディレクトリに移動
$ cd /usr/src/linux-6.8/

# カーネルイメージのコンパイル（x86_64では bzImage が生成される）
$ make bzImage
# または単に make でもカーネルイメージとモジュールを両方ビルドできる
$ make

# 並列ビルド（-j でCPUコア数を指定）
$ make -j$(nproc)        # nproc でCPUコア数を自動取得
$ make -j4               # 4並列でビルド
$ make bzImage -j$(nproc)  # カーネルイメージのみ並列ビルド

# カーネルモジュールのコンパイル
$ make modules -j$(nproc)

# コンパイル完了後の成果物の確認
$ ls -lh arch/x86/boot/bzImage
-rw-r--r-- 1 root root 11M arch/x86/boot/bzImage

並列ビルドによるコンパイル時間シミュレーター

CPUコア数と並列数を変えてコンパイル時間の目安を確認しましょう

4コア
1
推定コンパイル時間（フルビルド目安）
⚠️ コンパイルに関する注意事項
・フルビルドには数十分〜数時間かかります（スペックによる）
・-j の値はCPUコア数（nproc の出力）を目安にする
・コア数を大幅に超える値を指定するとメモリ不足になる場合がある
・コンパイル中はCPU・メモリを大量消費するため、本番サーバーでは避ける

⑥ インストール

重要ポイント④：make modules_install でモジュールを、make install でカーネルイメージをインストールする
make install は自動的に initramfs の生成と GRUB の設定更新も行います。

モジュールのインストール

# モジュールを /lib/modules// にインストール
$ sudo make modules_install
  INSTALL /lib/modules/6.8.0/kernel/drivers/hid/usbhid/usbhid.ko
  INSTALL /lib/modules/6.8.0/kernel/fs/ext4/ext4.ko
  ...
  DEPMOD  6.8.0   # modules.dep を自動生成

# インストール確認
$ ls /lib/modules/
6.8.0  6.8.0-51-generic

カーネルイメージのインストール

# カーネルイメージを /boot/ にインストール
# 以下のファイルが /boot/ にコピーされる：
#   vmlinuz-6.8.0  System.map-6.8.0  config-6.8.0
$ sudo make install
sh ./arch/x86/boot/install.sh 6.8.0 arch/x86/boot/bzImage \
        System.map "/boot"

# /boot の確認
$ ls -lh /boot/
-rw-r--r-- 1 root root  11M vmlinuz-6.8.0
-rw-r--r-- 1 root root 7.7M System.map-6.8.0
-rw-r--r-- 1 root root 287K config-6.8.0
-rw-r--r-- 1 root root  84M initrd.img-6.8.0-51-generic
...

initramfs の生成

# Debian / Ubuntu 系：initramfs を手動生成
$ sudo update-initramfs -c -k 6.8.0
#                       ↑-c：新規作成  ↑-k：カーネルバージョン指定
update-initramfs: Generating /boot/initrd.img-6.8.0

# 既存の initramfs を更新（現在のカーネル）
$ sudo update-initramfs -u

# すべてのカーネルの initramfs を更新
$ sudo update-initramfs -u -k all

# RHEL / CentOS 系：dracut を使用
$ sudo dracut --force /boot/initramfs-6.8.0.img 6.8.0

GRUBの更新

# Debian / Ubuntu 系：grub.cfg を自動更新
$ sudo update-grub
Sourcing file `/etc/default/grub'
Sourcing file `/etc/default/grub.d/init-select.cfg'
Generating grub configuration file ...
Found linux image: /boot/vmlinuz-6.8.0
Found initrd image: /boot/initrd.img-6.8.0
Found linux image: /boot/vmlinuz-6.8.0-51-generic
done

# RHEL / CentOS 系
$ sudo grub2-mkconfig -o /boot/grub2/grub.cfg

# GRUB設定の確認
$ grep menuentry /boot/grub/grub.cfg
menuentry 'Ubuntu, with Linux 6.8.0' ...
menuentry 'Ubuntu, with Linux 6.8.0-51-generic' ...
✅ make install が自動的に行うこと
make install を実行すると、ディストリビューションの install スクリプトが呼ばれ、 以下が自動的に実行されます：
① /boot/ へのカーネルイメージ・System.map・config のコピー
② update-initramfs（または dracut）による initramfs の生成
③ update-grub（または grub2-mkconfig）による GRUB 設定の更新

⑦ 再起動と確認

# システムを再起動
$ sudo reboot

# 再起動後：新しいカーネルで起動しているか確認
$ uname -r
6.8.0

$ uname -a
Linux hostname 6.8.0 #1 SMP PREEMPT_DYNAMIC Sat Jan 1 00:00:00 UTC 2026 x86_64 x86_64 x86_64 GNU/Linux

# モジュールが正しくインストールされているか確認
$ ls /lib/modules/6.8.0/
build  kernel  modules.alias  modules.dep  modules.symbols ...

# カーネルメッセージの確認（起動時のエラーがないか）
$ dmesg | grep -i error
$ dmesg | head -30

# 問題があった場合：GRUBメニューで旧カーネルを選択して起動
# 起動時に Shift キーを押してGRUBメニューを表示する
⚠️ 新しいカーネルで起動しない場合の対処
① 再起動時に Shift キー（BIOS）または Esc キー（UEFI）を押してGRUBメニューを表示
② 「Advanced options」から旧バージョンのカーネルを選択して起動
③ 旧カーネルで起動後、dmesg や /var/log/syslog でエラーを確認
④ 設定を修正して再コンパイル・再インストールを行う

📌 コンパイル手順まとめ

手順コマンド説明
① 準備 apt install build-essential libncurses-dev ... ビルドツールのインストール
② ソース取得 wget https://cdn.kernel.org/... kernel.org からソースをダウンロード
③ クリーン make mrproper ソースツリーを完全にクリーン（設定も削除）
④ 設定 make menuconfig .config ファイルの生成・編集
⑤ カーネルビルド make bzImage -j$(nproc) カーネルイメージ（bzImage）のコンパイル
⑥ モジュールビルド make modules -j$(nproc) カーネルモジュール（.ko）のコンパイル
⑦ モジュール配置 sudo make modules_install /lib/modules/<version>/ へのインストール
⑧ カーネル配置 sudo make install /boot/ へのコピー・initramfs生成・GRUB更新
⑨ 再起動 sudo reboot 新カーネルで起動
⑩ 確認 uname -r 新カーネルバージョンの確認

make の主要ターゲット一覧

ターゲット説明
make mrproperすべての生成ファイルと .config を削除（完全クリーン）
make clean生成ファイルを削除（.config は保持）
make menuconfigncurses ベースの設定ツールを起動
make oldconfig既存 .config を元に新オプションのみ対話設定
make olddefconfig既存 .config を元に新オプションをデフォルト値で設定
make defconfigアーキテクチャのデフォルト設定で .config を生成
make bzImagex86/x86_64 向け圧縮カーネルイメージをビルド
make modulesカーネルモジュール（.ko）をビルド
make modules_installモジュールを /lib/modules/<version>/ にインストール
make installカーネルを /boot/ にインストール・initramfs生成・GRUB更新
make allbzImage・modules を一括ビルド
