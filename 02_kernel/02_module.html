① カーネルモジュールとは

重要ポイント①：カーネルモジュールとは、カーネルを再起動せずに動的にロード・アンロードできる拡張機能
デバイスドライバ・ファイルシステム・ネットワークプロトコルなどが .ko（Kernel Object）ファイルとして提供されます。

必須コマンド一覧（クリックで詳細へジャンプ）

lsmod
ロード済みモジュールを一覧表示
modinfo
モジュールの詳細情報を表示
insmod
モジュールを直接ロード（依存解決なし）
rmmod
モジュールをアンロード
modprobe
依存関係を自動解決してロード・アンロード
✅ モジュールの格納場所
カーネルモジュール（.koファイル）は /lib/modules/$(uname -r)/kernel/ 以下に格納されています。
サブディレクトリ例：drivers/・fs/・net/・sound/・crypto/

② lsmod

重要ポイント②：lsmod は現在カーネルにロードされているモジュールの一覧を表示する
内部的には /proc/modules の内容を整形して表示しています。

基本的な使い方

# ロード済みモジュールの一覧表示
$ lsmod
Module                  Size  Used by
usbhid                 65536  0
hid                   139264  2 usbhid,hid_generic
snd_hda_intel          57344  3
snd_hda_codec         172032  4 snd_hda_intel,snd_hda_codec_generic
snd                   114688  16 snd_hda_intel,snd_hda_codec
e1000e                299008  0
...

# 特定モジュールが読み込まれているか確認
$ lsmod | grep usbhid
usbhid                 65536  0

# /proc/modules でも同じ情報を確認できる
$ cat /proc/modules | grep usbhid
usbhid 65536 0 - Live 0x0000000000000000

lsmod の出力フィールド解説

Module Size Used by
usbhid 65536 0
hid 139264 2 usbhid,hid_generic
snd_hda_intel 57344 3
↑ 各フィールドをクリックすると解説が表示されます

③ modinfo

重要ポイント③：modinfo はモジュールの詳細情報（説明・バージョン・依存関係・パラメータ）を表示する
モジュールをロードする前に情報を確認するために使います。

基本的な使い方

# モジュール名で情報を表示
$ modinfo usbhid
filename:       /lib/modules/6.8.0-51-generic/kernel/drivers/hid/usbhid/usbhid.ko.zst
version:        2.6
description:    USB HID core driver
license:        GPL
author:         Andreas Gal, Vojtech Pavlik, Jiri Kosina
srcversion:     A1B2C3D4E5F6
alias:          usb:v*p*d*dc03sc*in*
depends:        hid,usbcore
retpoline:      Y
intree:         Y
name:           usbhid
vermagic:       6.8.0-51-generic SMP preempt mod_unload
parm:           mousepoll:Polling interval of mice (uint)

# .koファイルのパスを直接指定
$ modinfo /lib/modules/$(uname -r)/kernel/drivers/hid/usbhid/usbhid.ko.zst

# 特定フィールドのみ表示（-F オプション）
$ modinfo -F description usbhid
USB HID core driver

$ modinfo -F depends usbhid
hid,usbcore

$ modinfo -F parm usbhid
mousepoll:Polling interval of mice (uint)

modinfo の主要フィールド

filename
モジュールファイル（.ko または .ko.zst）の絶対パス
description
モジュールの機能説明。何のドライバかを確認するのに使う
license
ライセンス（GPL・Proprietary など）。GPL以外はカーネルの一部機能が制限される場合がある
author
モジュールの作者情報
depends
このモジュールが依存する他のモジュール名。ロード前に依存モジュールが必要
alias
モジュールの別名。デバイスIDとモジュールの対応付けに使われる
vermagic
モジュールがコンパイルされたカーネルバージョン情報。実行中カーネルと一致しないとロード不可
parm
モジュールに渡せるパラメータ名と型。modprobe 時にパラメータを指定できる
⚠️ vermagic の重要性
vermagic フィールドのカーネルバージョンが実行中カーネルと一致しない場合、 モジュールはロードできません。
カーネルをアップデートした後は、モジュールも対応するバージョンのものを使用する必要があります。

④ insmod

重要ポイント④：insmod は .ko ファイルのフルパスを指定してモジュールを直接ロードする。依存関係の自動解決は行わない
依存するモジュールが未ロードの場合はエラーになります。 通常は依存関係を自動解決する modprobe を使うことが推奨されます。

基本的な使い方

# .koファイルのフルパスを指定してロード（root権限が必要）
$ sudo insmod /lib/modules/$(uname -r)/kernel/drivers/hid/usbhid/usbhid.ko

# パラメータを指定してロード
$ sudo insmod /lib/modules/$(uname -r)/kernel/drivers/hid/usbhid/usbhid.ko mousepoll=8

# 依存モジュールが未ロードの場合はエラーになる
$ sudo insmod /lib/modules/$(uname -r)/kernel/drivers/hid/usbhid/usbhid.ko
insmod: ERROR: could not insert module usbhid.ko: Unknown symbol in module
# → 依存モジュール（hid, usbcore）を先にロードする必要がある

# ロード確認
$ lsmod | grep usbhid
usbhid                 65536  0
⚠️ insmod の注意点
・.ko ファイルのフルパスを指定する必要がある
・依存関係を自動解決しないため、依存モジュールを手動で先にロードする必要がある
・通常の運用では modprobe を使うことが強く推奨される
・実行には root権限（または sudo）が必要

⑤ rmmod

重要ポイント⑤：rmmod はロード済みモジュールをアンロードする。他のモジュールが依存している場合はアンロードできない
lsmod の Used by が 0 のモジュールのみアンロード可能です。

基本的な使い方

# モジュール名を指定してアンロード（root権限が必要）
$ sudo rmmod usbhid

# 使用中のモジュールはアンロードできない
$ sudo rmmod hid
rmmod: ERROR: Module hid is in use by: usbhid hid_generic
# → 依存しているモジュール（usbhid, hid_generic）を先にアンロードする

# 強制アンロード（危険！使用中でも強制的にアンロード）
$ sudo rmmod -f hid
# ⚠️ システムが不安定になる可能性があるため通常は使用しない

# アンロード後の確認
$ lsmod | grep usbhid
# （何も表示されなければアンロード成功）

rmmod の依存関係エラー対処フロー

アンロードしたいモジュールを選択して、正しい手順を確認しましょう

⑥ modprobe（最重要）

重要ポイント⑥：modprobe は依存関係を自動解決してモジュールをロード・アンロードする。実運用では modprobe を使う
modules.dep ファイルを参照して依存モジュールを自動的に処理します。

基本的な使い方

# モジュール名を指定してロード（依存関係を自動解決）
$ sudo modprobe usbhid

# パラメータを指定してロード
$ sudo modprobe usbhid mousepoll=8

# モジュールをアンロード（依存関係を自動解決）
$ sudo modprobe -r usbhid

# 依存関係を表示（実際にはロードしない）
$ modprobe --show-depends usbhid
insmod /lib/modules/6.8.0-51-generic/kernel/drivers/hid/hid.ko.zst
insmod /lib/modules/6.8.0-51-generic/kernel/drivers/usb/core/usbcore.ko.zst
insmod /lib/modules/6.8.0-51-generic/kernel/drivers/hid/usbhid/usbhid.ko.zst

# ドライライラン（実際にはロードせず、実行内容を表示）
$ modprobe -n -v usbhid
insmod /lib/modules/.../hid.ko.zst
insmod /lib/modules/.../usbcore.ko.zst
insmod /lib/modules/.../usbhid.ko.zst

# すべてのモジュール情報を表示
$ modprobe -c

modprobe の設定ファイル

# modprobe の設定ファイルの場所
# /etc/modprobe.d/*.conf に設定を記述する

# 例1：モジュールのオプション（パラメータ）を永続設定
$ cat /etc/modprobe.d/usbhid.conf
options usbhid mousepoll=8

# 例2：モジュールのブラックリスト（ロードを禁止）
$ cat /etc/modprobe.d/blacklist.conf
blacklist pcspkr         # PCスピーカーモジュールを無効化
blacklist nouveau        # オープンソースNVIDIAドライバを無効化

# 例3：モジュールの別名（alias）を設定
$ cat /etc/modprobe.d/aliases.conf
alias net-pf-10 off      # IPv6モジュールの自動ロードを無効化

# 設定変更後は initramfs を再生成する
$ sudo update-initramfs -u

modules.dep ファイル（依存関係データベース）

# modules.dep の場所と内容
$ cat /lib/modules/$(uname -r)/modules.dep | grep usbhid
kernel/drivers/hid/usbhid/usbhid.ko.zst: kernel/drivers/hid/hid.ko.zst kernel/drivers/usb/core/usbcore.ko.zst
# usbhid は hid と usbcore に依存していることがわかる

# modules.dep を再生成するコマンド
$ sudo depmod           # 現在のカーネル用に再生成
$ sudo depmod -a        # すべてのカーネル用に再生成
$ sudo depmod -v        # 詳細表示付きで再生成

起動時の自動ロード設定

# 起動時に自動ロードするモジュールを設定
# /etc/modules-load.d/*.conf に記述する

$ cat /etc/modules-load.d/mymodules.conf
loop        # loopデバイスモジュールを起動時にロード
nbd         # ネットワークブロックデバイスモジュール

# 古い方式（/etc/modules）も有効
$ cat /etc/modules
loop
nbd

⑦ insmod vs modprobe 比較

比較項目 insmod modprobe
指定方法 .ko ファイルのフルパスを指定 モジュール名のみで指定可能
依存関係の解決 ❌ 自動解決しない ✅ 自動解決する
アンロード ❌ アンロード機能なし（rmmodを使う） ✅ modprobe -r でアンロード可能
設定ファイル参照 ❌ 参照しない ✅ /etc/modprobe.d/*.conf を参照
ブラックリスト対応 ❌ 対応しない ✅ blacklist 設定を尊重する
主な用途 開発・デバッグ時の直接ロード 通常の運用・スクリプト
root権限 必要 必要
✅ 実運用では modprobe を使う
insmod は依存関係を解決しないため、依存モジュールが未ロードの場合にエラーになります。 通常の運用では modprobe を使うことで、依存関係を自動解決して安全にロード・アンロードできます。 insmod は主にカーネル開発・デバッグ時に使用します。
